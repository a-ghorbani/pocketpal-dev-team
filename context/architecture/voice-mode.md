# Voice Mode Flow

> **Status:** on `main` since #1007. On-device ASR (#786, `asr.md`) is on main. Voice mode on the in-use Whisper tier (instead of base): on `main` since #1017.

## Purpose

Hands-free voice mode inside a chat: the user speaks, the reply is spoken, and the chat itself is the transcript. Covers entry (Plus entitlement and its teaser, model, setup, combined memory fit), the session controller and its state machine, the cascade engine (Whisper, the normal send path, TTS), interrupt handling, and the voice view and bar. Elsewhere: Whisper and dictation (`asr.md`), TTS engines and the stream (`tts.md`), the send path and keep-awake (`chat-flow.md`), purchases (`in-app-purchase.md`).

## How it works

`requestEntry`, in order: locked → the teaser (`sheet = teaser`, on every tap, nothing persisted). Its Get Plus closes it and calls `voiceEntitlement.source.openPaywall({onUnlocked})`, where `onUnlocked` re-runs `requestEntry` with the same actions; Keep typing closes it and calls `focusInput` on the next animation frame (called in the same tap, iOS dropped the focus while the overlay was still mounted); ✕, back, pull down and escape only close it (`dismissSheet`), and leaving the chat screen (blur) closes it too, but only the teaser: a setup or memory sheet stays open, so a Whisper download keeps going and still reaches `setupDone`; no `activeModelId` → ChatView's model picker (no resume after the pick); `isContextLoading` → nothing; setup incomplete (`asrStore.isSelectedTierReady` false, voice null or `system`, the voice's own file missing, mic not granted) → setup sheet, whose Continue downloads `asrStore.setupTier` (the default when nothing is installed, which then becomes the in-use tier as the first install), then `ensureVoiceFile` whatever the row showed (a download the reaction finished meanwhile counts; `false` sets the error line and stops, with no mic prompt and no `setupDone`; a voice changed during the download ends `proceed` silently, and the row re-checks the new voice), then (only if the sheet is still open and the app is not in the background; otherwise the sheet keeps Continue for one tap on return) `ensureMicPermission()` and `setupDone`. The sheet re-checks the mic (`isMicGranted`) when it opens and when the app returns to the foreground, so a grant in Settings replaces Open settings with Continue. `setupDone` re-runs the lock, model and loading checks before the memory fit (the model can be ejected during the download); then `checkMemoryAndEnter` re-checks the voice and its file (back to the setup sheet if either fails), reads `selectedTier` once and runs `voiceMemoryFit` for it: `fits` enters with that tier, `tight` / `wont_fit` open the memory sheet. Its Continue anyway (only on `tight`) closes the sheet and re-runs the lock, model and loading checks, since the sheet can stay open while the model is released or reloading; it enters with `fit.sttTier` only if that is still the in-use tier and ready, else it re-runs `requestEntry` (a fresh setup check and fit). Enter: `setVoiceOutputActive(true, {holdFirstChunk: model is local})`, `ttsStore.stop()`, one keep-awake hold, `starting` and `full` at once, `engine.prepare(tier)` (limited to `VOICE_START_TIMEOUT_MS`, 45 s), then `listening`. A failed or timed-out prepare, a failed `AudioRecord.init`, or a mic that stays silent shows a localized `uiStore.chatWarning` and exits. The keyboard is closed before entry.

```
closed ─enter→ starting ─prepared→ listening ─endpoint (hang | tap with speech | cap)→ transcribing
transcribing ─empty | VAD reject→ listening        ─throw→ listening (transcribe_failed)
transcribing | thinking ─tap→ cancel → listening
transcribing ─text→ thinking ─first chunk plays→ speaking ─run settled ∧ TTS idle→ listening
thinking ─settled, nothing spoken→ listening (reply_failed if it failed)
speaking ─tap→ interrupt → listening             ─finalize rejects→ listening (speech_failed)
any ─End | background | blur | chat switch* | activeModelId / contextId change | unmount | mic failure | video Pal (ChatScreen)→ closed
transcribing | thinking | speaking ─audio interruption began→ turn interrupted (as a tap) → listening, paused
starting | listening ─audio interruption began→ paused (mic off, shown muted; a load finishes into listening, paused) ─ended | cloud tap | app active | unmute→ listening, mic reopened
  * except the session a new chat's own spoken send creates (see Traps)
```

`micMuted` and `presentation` are independent of `phase`. A turn: `energyVad`, `whisperAsrEngine.transcribe` (the tier `prepare` pinned, the user's `spokenLanguage` if set, else auto-detect each turn; voice never writes it, so a misheard first turn can't lock dictation's language), `port.send(text, onTurnCreated)` (= `handleSendPress(…, {spoken: true, onTurnCreated})`), `speechStarted` when `ttsStore.voiceSpeechStarted` is this turn's id, `done` after the send settles and `playbackState` is idle.

## Contracts and invariants

- **Voice never writes the TTS gate or auto-speak.** One getter, `ttsStore.streamsReplies` (`voiceOutputActive || (isTTSAvailable && autoSpeakEnabled)`), opens the stream; with voice closed it equals the chat predicate (`tts.md`).
- **Single writers.** `phase` / `micMuted` / `lastError`: the controller only. `presentation`: `setPresentation` from the view, bar and back. `voiceOutputActive`: controller enter / exit. `unlockOverride`: E2E drivers, persisted only under `__E2E__`.
- **Voice turns are chat turns.** Every turn goes through `handleSendPress` under the generation lease; `applyEventToStore` stays the only store writer during a run. A reply's tool calls run concurrently (#999); interrupt and End stop the run through `handleStopPress`, whose abort cancels every call in flight. What is spoken follows chat auto-speak's step rules (`chat-flow.md`, Speech): call echoes are never spoken, a prose preamble before tools is, and `speaking` starts with the first audio.
- **An interrupted reply keeps what the model generated before the stop**, the same as a typed Stop: interrupt cancels the speech stream, stops the run and writes nothing back. Voice turns carry `metadata.spoken = true`; no row renders it.
- **Spoken replies run with thinking off** (`enable_thinking: false` and `reasoning: {enabled: false}` for a `{spoken: true}` send), whatever the chat or Pal says; typed turns are unchanged. `interrupt()` after `done` is a no-op.
- **Whisper is resident for the session**: `prepare(tier)` preloads and pins the in-use tier, read once in `checkMemoryAndEnter` and passed by value through the fit (`fit.sttTier`) and `enter`; the engine never reads `asrStore` for it, and a turn with no pinned tier fails as `transcribe_failed`. A tier switched in Settings under the open memory sheet makes Continue anyway re-run entry; an open session can't see a switch, since leaving the chat ends it. Nothing releases Whisper until exit. Every exit runs, in order: `phase = closed`, mic stop, `turn.interrupt()`, `setVoiceOutputActive(false)` (so a typed send right after End isn't spoken), `engine.release()` at idle (Whisper, and TTS unless `streamsReplies` still holds after `setVoiceOutputActive(false)`, i.e. chat auto-speak is on *and* TTS is available; auto-speak on with TTS unavailable still frees it), the keep-awake release. A re-entry awaits the previous exit.
- **Voice mode has its own device gate**: `high` / `flagship`, plus `mid` on iOS. `supported` is `userVoiceModeOverride ?? deviceSupported`: Settings' Hands-free voice switch (its own override, not dictation's) turns it on below the gate with a "May be slow" helper, or off on a capable phone. The entry memory check still applies. An iPhone 13 Pro (A15, 6 GB) is `mid` and answered in 2.8–5.6 s; Android's `mid` holds an 8 GB OnePlus 6 (SD845; Whisper alone 4–8 s). Dictation keeps its gate; the memory check still screens 4 GB iPhones.
- **Dictation's rules hold.** `wont_fit` is `whisperFits` for the in-use tier, dictation's rule. The two never overlap: the button needs dictation idle, and the composer is gone while a session is open.
- **No chat action starts a reply while a session is open**, bar included: the mic is open in `listening`, so a reply spoken outside a turn would be heard and sent back as the user's turn. ChatView gates the message menu's generating items and the suggested prompts on `isOpen`, and `PlayButton` disables replay on it, since a replay through the speaker would be transcribed the same way.
- **The mic runs only in `listening ∧ !micMuted`**, started by the controller's own transitions, never by a reaction on `phase`, so a forced phase starts nothing. No barge-in.
- **Neural voices only.** The `system` engine reports no chunk progress, which `speaking` needs.
- **Voice mode never enters with a voice whose file is missing**. Both controller checks, `isSetupComplete` and `checkMemoryAndEnter`, test the file (`isVoiceModeVoiceReady`, or `isVoiceModeVoice` and `hasVoiceFile` written out where the type guard must narrow `voice.engine`). The setup sheet is the one place that says a file is missing; the picker, the voice view and chat auto-speak show nothing (offline, chat auto-speak and replay of such a voice stay silent).
- **Voice mode is a Plus feature** (`handsFreeVoice`, shipped; `in-app-purchase.md`), and the paywall opens only from the teaser's Get Plus, never from the voice button itself. The default source is `unlockOverride ?? isPlusUnlocked()` (always unlocked in a build without the store gate, so the lock and teaser never show there), and its paywall is `openPlus({onUnlocked})`; `onUnlocked` re-runs entry once the Plus screen is dismissed unlocked. `register(source)` stays the seam for tests. E2E: `unlock::on|off` forces it, and `unlock::plus` clears the override so a FakeStore purchase decides.
- **The teaser is a picture, not a session.** It is a controller sheet, so `phase` stays `closed`: no `prepare`, mic, audio session, Whisper, TTS, keep-awake or permission prompt.
- **Memory rows are chat + Whisper + voice on both platforms**, against `memoryBudget`: Android `androidMemoryBudget`, iOS `ASR_IOS_CEILING_SHARE` (0.8) of the free memory it reported before any chat model loaded, `availableMemoryCeiling` (`asr.md`; later readings don't count mmap'd chat weights, and a pair that fit the full figure aborted Whisper's init). The share is applied once, in `memoryBudget`, so the sheet's available figure is the reduced one; 4B Q4 + Base won't fit at 4.2 GB. The stt row is the in-use tier's `runtimeBytes` (Small 650 MB, Large-turbo 1.2 GB); no lighter tier is offered from the sheet. Not yet known means `fits`. The sheet renders the rows as given.

## Traps and decisions

- **First audio at the first clause is the speech library's `firstChunk: 'clause'`** (`@pocketpalai/react-native-speech` 2.8.2, public API, no patch): the first chunk ends at the earliest of a sentence end, `[,;:—]`+space after 3 words, or 12 words. Its markdown buffer won't cut a first clause holding an inline marker (`*`, `_`, `` ` ``, `[`, `<`), so such a reply starts at its sentence end. Chat auto-speak never passes it.
- **Stream progress only marks that speech began** (`voiceSpeechStarted`); the engine strips markdown, as for chat auto-speak.
- **A local model holds the first voice chunk** until the reply settles or 1.5 s pass: synthesis next to decoding roughly doubled time to first audio on Pixel 9 / S23. Measured on CPU only, so every local backend holds; remote models never do.
- **The mic waits `VOICE_CAPTURE_SETTLE_MS` (150 ms) after a stop before it starts again.** On Android the old read thread releases the shared recorder when it ends, so a quick restart could lose the new one.
- **The mic reopens right after an `answered` turn on both platforms**, after only `VOICE_CAPTURE_SETTLE_MS`. The speech library (2.8.2) resolves iOS playback on `DataPlayedBack`, i.e. when heard, so no fixed tail guards `RNLiveAudioStream`'s switch to `PlayAndRecord`; Android's `AudioTrack` marker already fired at the last played frame. Don't reintroduce a tail: a cut-off reply end on iOS means completion regressed in the library.
- **The cloud tap is "done" while listening and "stop" after, and a tap always acts at once**. A tap in `transcribing` or `thinking` cancels the turn and one in `speaking` interrupts the reply, even one that lands just after the 600 ms hang ended the utterance (a late "done"); there is no grace window, by decision. The listening hint ("Pause when you're done, or tap the cloud to send") names the pause first so fewer users tap late.
- **A started mic that sends no audio within `VOICE_MIC_WATCHDOG_MS` (3 s; a Bluetooth headset's mic route takes 1–3 s) is restarted once, then voice mode ends.** One watchdog timer is live at a time: arming clears any pending one, so a `began` landing while an `openMic` is in flight can't leave a stray timer that restarts a healthy mic. Unmute resets the retry, so a retry spent before a mute doesn't end the session on a slow route afterwards. iOS `RNLiveAudioStream` only logs a failed start. Neither audio library reports route changes to JS, so it can't re-arm on one.
- **Audio interruptions come from the speech library** (`onAudioInterruption`, iOS `AVAudioSession` and Android audio focus). `began` stops the mic and, in `transcribing`, `thinking` or `speaking`, interrupts the turn exactly as a cloud tap does (model text kept, audio stopped). In those phases and in `starting` or `listening` (unmuted) it then pauses: the turn's return to `listening`, or the end of a model load, leaves the mic closed, since reopening it while a call or alarm holds the session ended voice mode with "Couldn't use the microphone". `ended` may never come (Android holds focus only while a chunk plays; iOS skips it after Siri and often after a call). An Android may-duck focus loss (a notification chime) is not an interruption: from 2.8.2 the library keeps playing at reduced volume and emits no event, so the turn goes on. Paused: `pausedByInterruption` set, `micMuted` set so the view shows "Microphone off", no watchdog and no cap, since a call holds the session for minutes and arming the 3 s watchdog there ended voice mode with "Couldn't use the microphone" while the phone rang. The pause resumes (`mic.restart` why `interruption_ended` / `tap` / `foreground`, unmuted, retry reset, fresh watchdog) on `ended`, a cloud tap, any change to `active` (iOS Siri goes `inactive`→`active` with no `ended`), or unmute; End and `background` exit as usual. A `began` while the user had muted leaves the mute theirs: `ended` doesn't unmute. Mic starts are serialised (`micStarting`), so overlapping restarts init the recorder once.
- **The controller is disposed with the chat screen**, so a late paywall `onUnlocked` starts nothing; the effect re-attaches it on mount (StrictMode).
- **The video-Pal exit lives in `ChatScreen`**: `VideoPalScreen` has no voice controls, so ChatScreen calls `end()` when `isVideoPal` turns true.
- **`prepare()` logs its two load times in dev builds only** (durations only). A first load took about 21 s, hence the `starting` hint and the 45 s limit.
- **Chunk-progress listeners stack** (since 2.6.0): each stream subscribes once and drops it on finalize or cancel, so a stream left neither would hear later streams' progress. A new stream starts only after the previous cancel resolves, and a turn ends only at `playbackState` idle.
- **`Speech.release()` during an active stream leaves its `finalize()` hanging.** A turn's interrupt awaits the stream cancel, and exit releases the models only after the interrupt (then at idle).
- **Phonon counts only where it is offered** (`tts.md`). `isVoiceModeVoice` rejects a Phonon voice unless `isEngineOffered('phonon')` (the same probe the picker filters on), so entry and the setup sheet ask for a supported voice instead. `PhononEngine.playStreaming` must forward `StreamOptions`, or `speaking` never starts. Its `TTS_ENGINE_RUNTIME_BYTES` row is 200 MiB; the key type is `NeuralEngineId`, so a new neural engine without a row fails to compile (`engineRegistry.test.ts` checks the keys too; `noImplicitAny` is off, so an unkeyed index would silently be `undefined`). Never size it from the iOS `phys_footprint` figure: that is only a lower bound. If Phonon's hide rule clears the voice mid-session, later replies are not spoken and the next entry opens setup. Setup's default voice is unchanged.
- **Keep-awake is counted** (`chat-flow.md`): the voice hold and a turn's hold coexist.
- **Exit on chat switch, background, blur and model change**: mic and Whisper can't run backgrounded, and the memory fit would be stale. One exemption: `activeSessionId` going from none to an id is ignored from the start of `port.send` until `onTurnCreated` (a new chat's first spoken send creates it), with model and context unchanged; any other switch closes the session. iOS `inactive` doesn't end it; back to `active` while listening restarts capture.
- **The view and bar follow the finger** in UI-thread gesture worklets: the view translates, dims and shrinks a little, then slides away and switches to the bar from the `withTiming` completion (`scheduleOnRN`), or springs back. Reduced motion: no follow, only the snap.
- **After End, the models are freed when the JS thread is idle** (`requestIdleCallback`; RN 0.87 removed `InteractionManager`), so the teardown doesn't land on a scroll. ChatScreen and ChatView read `isFullViewOpen` / `isOpen`, not `phase`, so a turn's phase changes don't re-render the chat; the cloud cancels its loops on unmount.
- **`transcribing` and `thinking` share one cloud look**; errors are a subtitle until the next phase change, since every failure resumes listening.
- **Overlay, not a route**: `useChatSession` must stay mounted, and the bar shares the chat.
- **Teaser before the paywall**: the locked button used to open Plus straight away, which users who had not chatted yet could read as "chatting costs money". The teaser shows what they tapped and a free way back to typing. It is an overlay like the view, not a `Modal`, so Keep typing can focus the composer one frame after it closes; the composer's own ref travels as `focusInput` through `onVoicePress`.
- **Android gets no automation deep-link hosts**, so voice captures there go through `VoiceAdapter` (`voice-command-input`).

- Unit: `src/services/voice/__tests__/` (interrupt races in `cascadeEngine`), `useVoiceMode.test.ts` (entry and the teaser, exits, mic, interruptions), `VoiceModeStore.test.ts` (gate), the `Voice*` component suites, `ChatScreen.voice*.test.tsx`, `ChatInput.test.tsx`, `ChatView.voiceInput.test.tsx`, `TTSStore.test.ts` (voice stream, hold, speech started), `voiceAutomation.test.ts`.

- By hand, on a high-tier Android phone and an iPhone with a neural voice, local model in airplane mode: a spoken turn (first audio before the reply ends; no thinking pass); a tap mid-speech stops speech and keeps the generated text; End while transcribing, thinking and speaking; mute; drag down to the bar and up again, slowly and with a flick; a tap while thinking cancels; AirPods connected at entry; chat scrolling right after End; iOS listening → speech → listening still captures; the screen stays on through a 2-minute silent listen and sleeps after End; second and third turns still reach `speaking`.
