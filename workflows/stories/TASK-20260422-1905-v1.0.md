## Context

### Background

On Samsung S26 Ultra (Adreno A8X), PocketPal's static OpenCL quant whitelist in `src/utils/deviceSelection.ts:222` (`['q4_0', 'q6_k']`) is wrong in **both** directions:

- Q5_K_M runs dramatically better on GPU than CPU (~300 vs 45 pp/s, 24 vs 18 tg/s) — should be allowed.
- Q2_K regresses TG by ~50% on GPU (9 vs 18 tg/s) — should be blocked or warned.

A static whitelist cannot capture this. We need **measured data** to drive the eventual fix. This task builds the measurement infrastructure ONLY — no product behaviour changes. Acting on the data (updating the whitelist, UX changes) is an explicit follow-up.

### Current State

- `src/screens/BenchmarkScreen/BenchmarkScreen.tsx` has a full UI benchmark flow that calls `modelStore.context.bench(pp, tg, pl, nr)` (llama.rn) and stores results in `benchmarkStore.results` via `addResult()`. Result includes `ppAvg`, `tgAvg`, `wallTimeMs`, `peakMemoryUsage`, model meta, and `initSettings` snapshot.
- `src/store/BenchmarkStore.ts` is MobX-persisted to AsyncStorage. `latestResult` getter returns `results[0]` (newest first via `unshift`).
- `llama.rn` exposes `bench(pp, tg, pl, nr): Promise<BenchResult>` with `speedPp`, `speedTg`, and config fields (`nGpuLayers`, `flashAttn`, `nThreads`, etc.) — see `node_modules/llama.rn/src/index.ts:304-323,904-933`.

### Target State

1. **New spec** `e2e/specs/benchmark-matrix.spec.ts` iterates `{models} × {quants} × {backends}` (default 3×8×2 = 48), driving the existing UI Benchmark screen for each cell. For each run:
   - Sets device tier via SettingsPage helper (CPU tier: `devices=['CPU'], n_gpu_layers=99`; GPU tier: `devices=[<adreno_name>], n_gpu_layers=99`).
   - Loads the model variant (GGUF for the specific quant).
   - Captures logcat during model load + benchmark to derive **effective backend**.
   - Reads benchmark result from on-device state (via new trigger helper, mirroring memory-snapshot pattern).
   - Writes one canonical JSON row per run.
2. **Canonical report** `e2e/debug-output/benchmarks/benchmark-<device_slug>-<commit_sha>.json` with full metadata (device, SoC, commit, llama_rn_version, timestamp) and per-run fields (model_id, quant, requested_backend, effective_backend, pp_avg, tg_avg, wall_ms, peak_memory_mb, log_signals, status).
3. **Compare tool** `e2e/scripts/benchmark-compare.ts` — mirror of `memory-compare.ts`. Diffs two reports row-by-row, flags regressions > 15% on pp or tg.
4. **Fixture schema extension** — `ModelTestConfig` gains optional `quants: ModelQuantVariant[]` alongside existing `downloadFile` (backward-compatible). Existing specs continue to use `downloadFile`.
5. **`run-e2e.ts` integration** — update `--spec benchmark-matrix` help text / examples; no runtime changes needed since spec resolution already works by filename.

## Requirements

### Functional

1. [MUST] Spec runs end-to-end on Android (S26 Ultra + Adreno A8X is the target device; spec must be device-agnostic on Android).
2. [MUST] Matrix defaults to 3 models × 8 quants × 2 backends = 48 runs; spec skips cells whose quant fixture is unavailable.
3. [MUST] Environment-variable filters: `BENCH_MODELS`, `BENCH_QUANTS`, `BENCH_BACKENDS` (comma-separated, case-insensitive).
4. [MUST] `MODELS_PRESEEDED=1` skips HF downloads entirely. Each spec pre-phase verifies the expected file is present on-device before benchmarking; in this mode, failure to find the file is a **skipped** run, not a failure.
5. [MUST] Even without `MODELS_PRESEEDED`, download wall-time is **never** counted in per-run timings — download is a separate pre-phase.
6. [MUST] `n_gpu_layers=99` is held constant across CPU and GPU tiers. Only `devices` changes. The CPU tier uses `devices=['CPU'], n_gpu_layers=99` (verified CPU-equivalent via `node_modules/llama.rn/cpp/llama-model.cpp:2747-2759`: every layer assigns to the CPU device regardless of `n_gpu_layers` when `devices=['CPU']`).
7. [MUST] For each run, spec captures logcat (Android) during model-load + benchmark and derives an **effective backend** label (`cpu` | `opencl` | `cpu+opencl-partial` | `unknown`) from OpenCL log signals. Report includes BOTH `requested_backend` and `effective_backend`.
8. [MUST] Spec writes one JSON report per run session: `e2e/debug-output/benchmarks/benchmark-<device_slug>-<commit_sha>.json`. The report is written incrementally after each run so that a mid-matrix crash preserves completed rows.
9. [MUST] `benchmark-compare.ts` diffs two reports, flags rows where |delta| > 15% on pp OR tg, exits 1 on any regression, 0 otherwise.
10. [MUST] Fixture schema change is backward-compatible: existing specs using `model.downloadFile` continue to work without modification.
11. [MUST] Default `bench()` call: `pp=512, tg=128, pl=1, nr=1`. (Note: `nr=1` chosen over `nr=3` to keep 48-run wall clock tractable; variance captured by re-running matrix rather than per-cell averaging. Raising `nr` is a per-session override — see Step 5).
12. [MUST] Spec is RUNNABLE but not wired into CI (CI integration is explicit out-of-scope).
13. [SHOULD] Default Gemma slot is `Gemma 3 1B` (bartowski `bartowski/google_gemma-3-1b-it-GGUF` has all 8 quants). If a quant is missing, swap is documented in fixture file, not silently dropped. Verification is an open question below — implementer confirms during Step 1.
14. [SHOULD] Hexagon NPU tier explicitly excluded from v1. Document in spec header as follow-up.

### Non-Functional

- Performance: Full matrix wall-time on S26 Ultra is bounded. Approximate budget per run: ~15-25 s for bench + ~20-40 s for load + ~5 s for device-tier switch = ~45 s/cell. 48 cells ≈ 35-45 min (pre-seeded). Spec must not have hard per-run timeouts tighter than 5 min for the worst-case quant.
- Compatibility: Android-first. iOS is explicitly out-of-scope (Metal has different fallback semantics).
- Security: None. Logcat output is app log only, not system-wide.

### Migration Considerations
- [x] Fixture schema change — `ModelTestConfig.quants?: ModelQuantVariant[]` is additive and optional. No user data affected (E2E-only config).
- No backwards compat concerns for end users. No stored data affected.
- Migration strategy: `none needed`.
- Files/paths affected: `e2e/fixtures/models.ts` schema only.

/** Helper: filter matrix by env vars */
export function getBenchmarkMatrix(): {
  models: ModelTestConfig[];
  quants: string[];
  backends: ('cpu' | 'gpu')[];
} {
  const modelFilter = process.env.BENCH_MODELS?.split(',').map(s => s.trim().toLowerCase());
  const quantFilter = process.env.BENCH_QUANTS?.split(',').map(s => s.trim().toLowerCase());

  return {models, quants, backends};

**Code Guidance**:
```typescript
import {spawn, execSync} from 'child_process';

export interface LogcatCapture {
  lines: string[];
  stop(): string[]; // returns captured lines, also accessible via .lines
}

const BENCH_LOG_RE = /(lm_ggml_opencl|ggml_backend_|Adreno large buffer|offloaded|load_tensors:|llama_model_load|ggml_cl)/;

export function startCapture(udid?: string): LogcatCapture {
  const base = udid ? ['-s', udid] : [];
  execSync(['adb', ...base, 'logcat', '-c'].join(' '), {timeout: 5000});
  const proc = spawn('adb', [...base, 'logcat', '-v', 'brief']);
  const lines: string[] = [];
  proc.stdout.on('data', (chunk: Buffer) => {
    for (const line of chunk.toString('utf8').split('\n')) {
      if (BENCH_LOG_RE.test(line)) lines.push(line);
    }
  });
  return {
    lines,
    stop() { proc.kill('SIGTERM'); return lines; },
  };
}
```

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| **1. `n_gpu_layers=99` constancy violated when selecting CPU tier** — `DeviceOption.cpu` in `src/utils/deviceSelection.ts:102-112` forces `n_gpu_layers: 0`. If we cannot drive the slider back to 99 via Appium text input on the `gpu-layers-slider` InputSlider, the CPU tier will run with `n_gpu_layers=0`. Under `devices=['CPU']` this is functionally equivalent (brief verified via `llama-model.cpp:2747-2759`). Mitigation: document the effective equivalence in the report's notes field, and in the README. Cleanest test-time override would be a new `set-devices` deep-link but that touches src/. Accept: with `devices=['CPU']`, `n_gpu_layers` value is immaterial. The single-variable hygiene is still preserved (only `devices` actually changed runtime behaviour). | High | Medium | Document + accept. If critic disagrees, escalate — we MUST NOT touch src/ to solve this. |
| **2. UI result-card scrape is fragile** — Label text depends on l10n; the `BenchResultCard` has testIDs only on delete/share buttons, not on pp/tg values. | Medium | Medium | Start with text-anchored scrape: find "Prompt Processing" label, then the adjacent numeric TextView. If flaky across 48 runs, add `testID="pp-avg-value"` / `testID="tg-avg-value"` to `BenchResultCard.tsx` — this IS a product-code change, but it's testability improvement, not behaviour change. Re-classify the task as needing src/ changes if required. Flag in Open Questions. |
| **3. HF model IDs don't have all 8 quants** | Medium | Low | Step 1 verifies manually; swap nearest rung + document in fixture comment. Never silently drop. |
| **4. logcat capture misses signals due to buffer overflow** — `adb logcat` has a ring buffer; on a busy phone lines can drop. | Low | Medium | Use `adb logcat -G 4M` to expand buffer before each run; `-c` to clear. If lines still missing, widen the filter. |
| **5. 48-run wall time exceeds reasonable budget (> 90 min)** | Low | Low | Default `nr=1` keeps per-cell bench short. Fallback: env-var filter reduces matrix. Session-level progress logging lets human abort mid-run. |
| **6. Model download for IQ1_S / Q8_0 variants is slow/network-bound** | Medium | Low | `MODELS_PRESEEDED=1` bypasses entirely; document how to preseed via `adb push` + note the on-device model path in README. |
| **7. Fixture schema change breaks existing specs** | Low | High | New field is optional; existing `downloadFile` stays required. `cd e2e && yarn typecheck` must pass as an acceptance gate. |
