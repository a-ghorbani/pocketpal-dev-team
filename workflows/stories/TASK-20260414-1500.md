## Context

### Background
PR #688 landed v1.2 of on-device TTS: a single neural engine (Supertonic, multilingual) plus the OS fallback, behind a bottom-sheet voice picker. The neural pipeline is wrapped by `@pocketpalai/react-native-speech`, currently pinned to a GitHub SHA install. That fork has since published **`@pocketpalai/react-native-speech@2.0.0`** to npm (2026-04-14) which ships prebuilt `lib/` *plus* two additional neural engines: **Kokoro** (high-quality multilingual) and **Kitten** (lightweight StyleTTS2, English). This task wires those two engines into PocketPal, reorders the setup sheet, exposes a Supertonic diffusion-steps selector, and switches the dependency from the GitHub SHA to the npm release.

### Current State (on `feature/TASK-20260412-1743-v1.2`)
- `src/services/tts/types.ts` — `EngineId = 'system' | 'supertonic'`.

### Fork research (npm 2.0.0, pulled via `npm pack` + fork GitHub)
- **Published**: `@pocketpalai/react-native-speech@2.0.0` — 2026-04-14, ships prebuilt `lib/module`, `lib/typescript`, native `ios/`, `android/`, `cpp/`. Exports `TTSEngine.{OS_NATIVE, KOKORO, SUPERTONIC, KITTEN}`, per-engine config types, `ExecutionProviderPreset = 'auto' | 'cpu' | 'gpu' | 'ane'`.
- **CPU-only**: every neural config accepts `executionProviders?: ExecutionProviderPreset | ExecutionProvider[]`. Default is `'auto'` (CoreML/NNAPI). Passing `'cpu'` forces CPU-only across all three engines uniformly. Supertonic currently omits the option → uses `'auto'` today. This story threads `executionProviders: 'cpu'` into all three neural `Speech.initialize()` calls.
- **Supertonic steps**: `SupertonicConfig.defaultInferenceSteps?: 1|2|3|4|5|10|20|50` (default 5). Per-call override via `SupertonicSynthesisOptions.inferenceSteps`. Fewer steps = faster, lower quality.
- **Kokoro**: `KokoroConfig { modelPath, voicesPath, tokenizerPath, dictPath?, maxChunkSize?, executionProviders? }`. Q8 variant URL: `https://huggingface.co/onnx-community/Kokoro-82M-v1.0-ONNX/resolve/main/onnx/model_q8f16.onnx`. Tokenizer: `tokenizer.json` at repo root. Voices: per-voice `.bin` under `voices/` (28 voices listed in example `ModelManager.ts`). Apps create a local manifest `voices-manifest.json` that points at `voices/{voiceId}.bin`. Phonemizer defaults to MIT `phonemize` (no dict download needed).
- **Kitten nano-fp32**: model `https://huggingface.co/palshub/kitten-tts-nano-0.8-fp32/resolve/main/kitten_tts_nano_v0_8.onnx` (~57 MB), manifest `voices-manifest.json` at same repo. `KittenConfig { modelPath, voicesPath, tokenizerPath?, dictPath?, maxChunkSize?, executionProviders? }`. 8 voices (Bella, Jasper, Luna, Bruno, Rosie, Hugo, Kiki, Leo). English only.
- **Memory guidance from fork README**: "Neural engines recommend a 3 GB+ RAM device. Low-memory devices should prefer the Kitten nano/micro variants or fall back to OS_NATIVE." Per-engine RSS: Kitten 80–150 MB, Kokoro 150–250 MB, Supertonic 150–250 MB.

## Memory gate

| Kokoro voices download: 28 `.bin` files = 28 HTTP requests → fragile on flaky networks | Medium | Medium | **Two-phase install**: Phase 1 downloads `model.onnx` + `tokenizer.json` — any failure here cleans up the whole `tts/kokoro/` dir and reports error (engine unusable without these). Phase 2 downloads the 28 voice `.bin` files — failures here do NOT wipe the directory; instead mark the engine as "installed with partial voices" and surface whichever voices did land. | Android NDK / onnxruntime native libs bloat APK noticeably | Low | Medium | Verify APK size delta during Android release build; document in PR. |
| `deleteKitten/deleteKokoro` runs while `currentVoice` is a voice from that engine → silent crash on next play | Medium | Medium | In the store, if delete is called and `currentVoice.engine === <that engine>`, clear `currentVoice`.
