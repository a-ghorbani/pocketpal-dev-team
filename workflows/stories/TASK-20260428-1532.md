### Background

PR #702 added a benchmark-matrix E2E spec (`e2e/specs/benchmark-matrix.spec.ts`, ~505 LOC) that drives the in-app Benchmark screen across {2 models} × {8 quants} × {2 backends} = 32 cells, reading results out via a hidden `BenchmarkAdapter` (TextInput + Text accessibilityLabel pair, mounted in the AutomationBridge introduced by TASK-20260423-2331).

Live device run on POCO Myron (Snapdragon 8 Elite Gen 5 / Adreno 840v2, HyperOS 16) timed out at Mocha's 10-minute spec limit. Investigation:

- `setDeviceTier(gpu)` on Settings screen worked after a 30s-timeout fix (already committed as `25d8785`).
- After the tier switch, the spec sent `read::initSettings` to `BenchmarkAdapter`'s hidden TextInput. The `setValue` command landed (the `benchmark-result-label` testID was found), but the corresponding `benchmark-result-value` accessibilityLabel was never readable from the Settings screen — `WDIO.findElements` consistently returned `[]`.
- The trigger DOES work on the Chat screen (confirmed by an earlier UI dump). Suspected cause: HyperOS / RN's accessibility-tree exclusion of opacity-0 absolute-positioned views when overlaid by a full-screen content area + native drawer state.
- Secondary bug: `e2e/helpers/benchmark.ts:readResultRaw()` has a 10s timeout that doesn't fire because WDIO's lazy `$()` proxy + `getAttribute('content-desc')` swallows `NoSuchElementError` into empty-string returns; the helper polls indefinitely without terminating.

Both bugs could be fixed in place, but the architecture is wrong for this use case. The hidden-trigger pattern was inherited from `MemoryAdapter` and is appropriate THERE because memory profiling instruments the regular UX flow (snapshot at "model loaded", "after first inference", etc. across the actual screens a user sees). Benchmark-matrix is the opposite: it's a synthetic harness that doesn't need to instrument the regular UX flow — it just needs to drive `context.bench()` programmatically and emit a JSON report.

User's call:

> "since we have a specific build, why do we have hidden screen? this is e2e build so for benchmark we can have a real screen"

So we replace the hidden trigger + cross-screen WDIO orchestration with a real, dedicated, E2E-only screen reachable by deep link. The spec collapses to "launch screen, tap one button, poll status, pull JSON".

### Why the deep link approach (vs `--es extra` / direct activity launch / native module)

- `mobile: deepLink` (Appium) and `adb shell am start -a android.intent.action.VIEW -d "pocketpal://e2e/benchmark"` are equivalent — both end up as a VIEW intent against any activity that registers a matching intent-filter. This is React Native's standard `Linking.getInitialURL()` path on Android.
- It reuses the existing `dispatchAutomationDeepLink` pipe (`useDeepLinking.ts` → `__automation__/deepLink.ts`) — no new native module, no new event emitter.
- The intent-filter goes ONLY in `android/app/src/e2e/AndroidManifest.xml` (flavor source-set merge). The prod APK gets no `pocketpal://` scheme registration. Two-tier defence-in-depth: app code is DCE'd (no JS dispatcher in prod) AND the OS-level intent route doesn't exist.
- The E2E spec always launches the activity from a clean state (`fullReset: true` in WDIO config) — every deep link is a cold-launch. This is why `Linking.getInitialURL()` (which reads the launching intent's data URI) is sufficient and we don't need `Linking.addEventListener('url', ...)` / `onNewIntent` overrides on Android.

## Pre-agreed Design (from orchestrator brief — do not re-litigate)

### 1. NEW SCREEN: `src/__automation__/screens/BenchmarkRunnerScreen.tsx` (~250 LOC target)

Mounted only when `__E2E__`. Reachable via deep link only — NOT in the user-visible drawer. UI:
- Title text: "Benchmark Matrix Runner" (visible, helps screenshot debugging)
- Status `<Text testID="bench-runner-screen-status" accessibilityLabel={status}>{status}</Text>` whose text moves through `idle → downloading:<name> → running:<i/total>:<model_id>/<quant>/<backend> → complete | error:<short_msg>`
- "Run benchmark matrix" button (`testID="bench-run-button"`) — manual tap, NOT auto-on-mount. Rationale (per user): "gives screenshot-able state, avoids surprise auto-runs"
- "Reset" button (`testID="bench-reset-button"`) — clears status back to `idle` (not strictly required for v1 but tiny addition; see OPEN DECISIONS)
- Live result preview: last cell's `pp` / `tg` / `cell_count` plus a count of completed/total cells (read-only Text rows; container `testID="bench-runner-screen-result-preview"`)

The screen does NOT modify navigation history beyond the Drawer entry — once mounted, `goBack()` returns to whatever screen the user was on. (Doesn't matter for E2E since the spec ends with the screen still on top.)

### 2. MATRIX ITERATION INSIDE THE SCREEN

Reads matrix config from `RNFS.ExternalDirectoryPath/bench-config.json` (adb-pushable; see Step 1 in Implementation Plan). Per cell:

```
1. Update bench-runner-screen-status to "downloading:<filename>" if file not local;
   call modelStore.downloadHFModel({...}) and await its completion via a
   downloadManager.subscribe pattern OR a polling loop on modelStore.models
   (whichever is smaller; planner notes this in Step 1).
2. Update bench-runner-screen-status to "running:<i/total>:<model_id>/<quant>/<backend>"
3. Set tier programmatically: modelStore.setDevices(cellDevices)
4. modelStore.initContext(model)  // mutex-serialized; blocks until ready
5. {speedPp, speedTg} = await modelStore.context.bench(pp, tg, pl, nr)
6. Capture peakMemoryUsage + wallTimeMs + initSettings (snapshot of
    modelStore.contextInitParams at the moment of the call)
7. modelStore.releaseContext()  // free GPU/CPU before next cell
8. report.runs.push({...}); RNFS.writeFile(reportPath, JSON.stringify(report))  // append-as-you-go
```

When matrix done: status → `complete` (the report file already contains the final state from step 8).

`pp/tg/pl/nr` come from a single config block (the spec writes whatever `BenchmarkConfig` it wants to use; default = `{pp: 512, tg: 128, pl: 1, nr: 3}` — same as `BenchmarkScreen` Default preset).

### 3. SPEC COLLAPSES TO ~80 LOC

```
1. Install APK (run-e2e.ts pre-spec — already plumbed)
2. Write bench-config.json to a tempdir
3. adb push bench-config.json /sdcard/Android/data/com.pocketpalai.e2e/files/bench-config.json
4. Launch via mobile: deepLink with url=pocketpal://e2e/benchmark, package=com.pocketpalai.e2e
5. Wait for bench-run-button visible, tap it
6. Start logcat capture (whole-run)
7. Poll bench-runner-screen-status accessibilityLabel for /^complete$|^error:/ with long timeout (~60 min for 32 cells; configurable BENCH_MAX_WAIT_MIN env var)
8. Stop logcat
9. adb pull /sdcard/Android/data/com.pocketpalai.e2e/files/benchmark-report-*.json e2e/debug-output/benchmarks/
10. Slice logcat by per-cell timestamps from the pulled report; attach derived log_signals + effective_backend per row; rewrite the JSON
```

No drawer navigation. No SegmentedButton tap. No tier-switch precondition assertion (we drove `setDevices` programmatically — no race vs. handleDeviceSelect). No accessibility-tree dependency on a hidden View.

### 4. LOGCAT CAPTURE

Whole-run capture + slice-after-the-fact (not per-cell start/stop). Rationale: cleaner spec code, only one `adb logcat` process spawned, and `e2e/helpers/logcat.ts` already exposes a stream of timestamped lines that can be sliced by `<= cell_start_ms ... <= cell_end_ms`. The report's per-cell `timestamp` (ISO string) plus `wall_ms` defines the window.

`deriveLogSignals(slice)` and `deriveEffectiveBackend(signals)` are already exported by `e2e/helpers/logcat.ts` — no helper changes needed.
