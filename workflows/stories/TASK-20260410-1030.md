### Background
Google Play rating is declining due to expectation mismatch. Users download the app expecting ChatGPT-level cloud AI and leave negative reviews when they encounter local inference limitations. New copy uses identity-mirroring positioning to attract the right users and set realistic device expectations upfront.

Additionally, the Fastfile currently skips metadata upload (`skip_upload_metadata: true`), meaning Play Store listing text must be updated manually. Flipping this flag enables automated metadata deployment during the release lane.

- `fastlane/metadata/android/en-US/short_description.txt`: Generic description ("PocketPal is an app for secure and private conversation with open source LLMs")
- `fastlane/metadata/android/en-US/full_description.txt`: Feature-list copy (12 lines), mentions "Private AI Chat" brand name no longer used
- `android/fastlane/Fastfile` line 41: `skip_upload_metadata: true` — metadata not uploaded during releases
- `android/fastlane/Fastfile` has no `metadata_path` parameter — `supply` would look for metadata at `android/fastlane/metadata/android/` (wrong location)

### Target State

- Fastfile: `skip_upload_metadata: false` with explicit `metadata_path` pointing to the correct `fastlane/metadata/android` directory at repo root

### Step 3: Enable metadata upload in Fastfile with correct path
**Files**: `android/fastlane/Fastfile`
**Status**: `DONE`

**Why metadata_path is needed**: The CI workflow (`release.yml` line 120) sets `working-directory: android` before running Fastlane. This means `Dir.pwd` inside the Fastfile is `<repo>/android/fastlane`. Fastlane's `supply` tool defaults to looking for metadata at `<fastlane_dir>/metadata/android/` which resolves to `android/fastlane/metadata/android/` — a directory that does not exist. The actual metadata lives at `<repo>/fastlane/metadata/android/en-US/`. Without an explicit `metadata_path`, enabling metadata upload would either crash or silently skip.

**Changes**:
- [ ] Line 41: Change `skip_upload_metadata: true` to `skip_upload_metadata: false`
- [ ] Add `metadata_path` parameter to `upload_to_play_store` call

The existing `android_dir` variable (line 6) resolves to `<repo>/android`. Use it to construct the correct path to repo root:

```ruby
# Line 6 already defines: android_dir = File.expand_path('..', Dir.pwd)
# android_dir = <repo>/android

upload_to_play_store(
  track: "alpha",
  package_name: "com.pocketpalai",
  skip_upload_metadata: false,
  skip_upload_images: true,
  skip_upload_screenshots: true,
  skip_upload_apk: true,
  metadata_path: File.join(android_dir, "..", "fastlane", "metadata", "android"),
  json_key: File.join(android_dir, "play-store-key.json")
)
```

**Pattern note**: The Fastfile already uses `android_dir` with relative path joins (e.g., `File.join(android_dir, "app/google-services.json")`). Using `File.join(android_dir, "..", "fastlane", "metadata", "android")` follows the same pattern to navigate to repo root.
