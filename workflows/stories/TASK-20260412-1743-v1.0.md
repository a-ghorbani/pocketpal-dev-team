3. **[MUST]** Create `src/store/TTSStore.ts` with observable state:
   - `isTTSAvailable: boolean` — set once at init from `DeviceInfo.getTotalMemory() >= TTS_MIN_RAM_BYTES`. Never re-checked.
   - `playbackState: 'idle' | 'loading' | 'playing'`
   - `currentMessageId: string | null`
   - `autoSpeakEnabled: boolean` (persisted; default `false`)
   - `currentVoice: Voice | null` (persisted; default `null`)
   - `isSetupSheetOpen: boolean`
   - `lastSpokenMessageId: string | null` — ref-style guard

   Actions:
   - `init()` — reads memory, sets `isTTSAvailable`. If true: `configureAudioSession()`, registers AppState listener (stop on background), registers `reaction` on `chatSessionStore.activeSessionId` to stop. If false: no-op (no listeners registered, feature dead on this device).
   - `play(messageId, text, voiceOverride?)` — stops any in-flight playback; resolves engine from `voiceOverride?.engine ?? currentVoice?.engine`; updates `playbackState`, `currentMessageId`. If engine is Supertonic and stub throws → set state to `idle`, swallow error in v1.0 (real error UX in v1.2).
   - `stop()` — stops engine, resets state.
   - `setAutoSpeak(on)`, `setCurrentVoice(v)`, `openSetupSheet()`, `closeSetupSheet()`.
   - `onAssistantMessageComplete(messageId, text)` — if `isTTSAvailable && autoSpeakEnabled && currentVoice != null && messageId !== lastSpokenMessageId`: set `lastSpokenMessageId = messageId`, call `play(messageId, text)`.

   Persistence: use the same mechanism as `UIStore` (MobX persist pattern). Persist only `autoSpeakEnabled` and `currentVoice`.

4. **[MUST]** Register `ttsStore` in `src/store/index.ts`. Verify the store count in that file goes from 9 to 10.

5. **[MUST]** In `src/hooks/useChatSession.ts`, at approximately line 357 (the final `updateMessage()` call that writes `completionResult: { reasoning_content, content }` — the PR #578 location), after the `updateMessage()` call, invoke:

6. **[MUST]** Root-level `init()` call: TTSStore must be initialized at app start. Add the `init()` call to the same place other stores are initialized (grep `ModelStore` init/hydrate for the pattern).

### Post-install caveats (discovered during implementation)

The WIP fork ships without a built `lib/` directory and depends on git submodules
that yarn's GitHub tarball fetch does not populate. Three manual steps were
required to get native builds working; these need to be automated (postinstall
script) before the PR is merged, OR documented in `CONTRIBUTING.md`.

1. **TypeScript shim**: the package has no prebuilt typings and `bob build
   --target typescript` fails against RN 0.82. Workaround: `src/types/shims/mhpdev-react-native-speech.d.ts`
   declares the subset of the API we call (`speak`, `stop`, `getAvailableVoices`,
   `VoiceProps`). Remove the shim when the published package ships real `.d.ts`.

2. **espeak-ng submodule**: `node_modules/@mhpdev/react-native-speech/third-party/espeak-ng/`
   ships empty because yarn does not pull git submodules from GitHub tarballs.
   To populate:
   ```bash
   cd node_modules/@mhpdev/react-native-speech/third-party
   git clone https://github.com/espeak-ng/espeak-ng.git
   cd espeak-ng
   git checkout b0b605c8a80f76c4c19e18033c6780c3cc4afc5b
   git submodule update --init --recursive   # pulls ucd-tools
   ```
   Without this, the iOS `Build espeak-ng static library` script phase fails
   with `cp: .../libespeak-ng/config.h: No such file or directory`.

3. **Pod install ordering**: the RNSpeech podspec declares `vendored_frameworks
   = 'ios/build-espeak/libespeak-ng.xcframework'`. That path does not exist
   until the `before_compile` script runs, so the FIRST `pod install` does not
   add the framework reference to `Pods.xcodeproj`. After the first iOS build
   attempt generates the xcframework, run `bundle exec pod install` a second
   time to register the framework, then rebuild. This re-pod-install is a
   one-time step per fresh checkout.

### Missing non-committed config (not related to this story)
