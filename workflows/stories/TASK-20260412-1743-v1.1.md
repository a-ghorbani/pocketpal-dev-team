## Context

### Background
v1.0 delivered the TTS foundation: service stubs, TTSStore with memory gate, assistant-message-complete callback wiring. No UI was added. This sub-story adds all the user-facing UI (play button, input-bar split chip, setup sheet, settings row) and makes the **System TTS path** work end-to-end on iOS and Android. The **Supertonic section is visible in the setup sheet but disabled/placeholder** — it's wired live in v1.2.

### Current State (after v1.0 merged into integration)
- `TTSStore` exists with `isTTSAvailable`, `currentVoice`, `autoSpeakEnabled`, `play`, `stop`, `openSetupSheet`, etc.
- `SystemEngine` works. `SupertonicEngine` is a stub throwing on `play()`.
- No UI components yet.
- `src/components/TextMessage/TextMessage.tsx` renders assistant messages (ChatView wires at `ChatView.tsx:186,721,742`).
- `src/components/ChatInput/ChatInput.tsx` (~632 lines).
- `src/screens/SettingsScreen/SettingsScreen.tsx` (~1174 lines).
- `@gorhom/bottom-sheet` is already in use elsewhere.

### Target State
- `PlayButton` component integrated into `TextMessage.tsx`. Guards: assistant-only, `>1` word, post-streaming, `isTTSAvailable`. Icon swap speaker ⇄ stop. No morph, no progress, no long-press.
- `VoiceChip` component integrated into `ChatInput.tsx` left of the text field. Implements split-chip pattern per Luke Wroblewski spec: 5 visual states, ≥44pt per half, vertical divider, responsive truncation (full → 3 chars → icon-only), gear always visible.
- `TTSSetupSheet` mounted at **app root** (not chat root) so it's reachable from anywhere. Contains `SupertonicSection` (first, with "install to use" placeholder since the engine is stubbed) + `SystemSection` (working, labeled `"System voices · robotic, for accessibility"`).
- Settings Voice & Speech section (Voice / Preview rows) opens the setup sheet.
- **System TTS path works end-to-end**: tap play on a message → sheet opens (no voice yet) → pick System voice → sheet dismisses → playback begins via `SystemEngine`.
- Supertonic section is visible, ordered first, but all its voice rows show a disabled state and their Preview buttons are **non-functional placeholder** (planner chose: disabled state, tapping shows no effect; simpler than a tooltip).

## Requirements

### Functional

1. **[MUST]** `src/components/TextMessage/PlayButton.tsx`:
   - Render only if: `ttsStore.isTTSAvailable && assistantTextMessage && trimmedWordCount > 1 && !isStreaming`.
   - Observer-wrapped at the button level (not the whole message).
   - If `currentVoice == null`: tap → `ttsStore.openSetupSheet()`. No audio plays.
   - Else if `currentMessageId === messageId && playbackState === 'playing'`: tap → `stop()`.
   - Else: tap → `play(messageId, text)`.
   - Icon: speaker (idle for this message) ↔ stop (playing for this message). Simple swap. ≥44pt tap target.

2. **[MUST]** Integrate `PlayButton` into `src/components/TextMessage/TextMessage.tsx` near the existing message action/render area. Render nothing when guards fail.

3. **[MUST]** `src/components/VoiceChip/VoiceChip.tsx`:
   - Gated render: return `null` if `!ttsStore.isTTSAvailable`.
   - Pre-setup (`currentVoice == null`): single gear `IconButton` (NOT split; no toggle half, no divider). Tap → `openSetupSheet()`. ≥44pt tap target.
   - Voice-chosen: horizontal row with two `Pressable`s separated by a 1px vertical divider:
     - **Left half** (≥44pt wide): tap toggles `autoSpeakEnabled`. Renders speaker icon by state + voice name label:
       - OFF + voice set: outline speaker + voice name
       - ON + idle: filled speaker + voice name
       - ON + playing: animated 3-bar waveform + voice name
     - **Right half** (≥44pt wide): gear icon. Tap → `openSetupSheet()`.
   - Responsive truncation for the voice name label: full → first 3 chars → icon-only, based on chip width. Use `onLayout` measurement or a simple width-breakpoint heuristic (implementer picks the simpler approach that passes visual review).
   - Accessibility: each half has its own `accessibilityLabel` ("Toggle auto-speak" / "TTS settings").

4. **[MUST]** Mount `<VoiceChip />` in `src/components/ChatInput/ChatInput.tsx` left of the text input.

5. **[MUST]** `src/components/TTSSetupSheet/TTSSetupSheet.tsx`:
   - Built with `@gorhom/bottom-sheet`. Single instance, mounted once at the **app root** (not chat root), opens when `ttsStore.isSetupSheetOpen`.
   - Composition: `<SupertonicSection />` rendered FIRST, `<SystemSection />` rendered BELOW.

6. **[MUST]** `src/components/TTSSetupSheet/SupertonicSection.tsx`:
   - Section header + brief copy: "Natural on-device neural voices."
   - Shows an "Install to use" placeholder card (non-functional in v1.1 — v1.2 wires the download).
   - For each of the 10 Supertonic voices: a row with voice name and a **Preview button that is non-functional (disabled state)**. Tapping the row body does NOT select the voice in v1.1 (rows are disabled until v1.2 enables them).

7. **[MUST]** `src/components/TTSSetupSheet/SystemSection.tsx`:
   - Section header: `"System voices · robotic, for accessibility"` (l10n key).
   - Lists voices from `SystemEngine.listVoices()` at sheet open.
   - Each row: voice name + Preview button (synthesizes `TTS_PREVIEW_SAMPLE` with that System voice, ignoring `currentVoice`).
   - Tap row body → `ttsStore.setCurrentVoice({ engine: 'system', voiceId, displayName })` + `closeSetupSheet()`.
   - No search input. No auto-audition.

8. **[MUST]** Settings → Voice & Speech section in `src/screens/SettingsScreen/SettingsScreen.tsx`:
   - Conditionally render only if `ttsStore.isTTSAvailable`.
   - Voice row: title `"Voice"`; subtitle = `currentVoice?.displayName ?? t('voiceAndSpeech.notSet')`. Tap → `openSetupSheet()`.
   - Preview button row: disabled if `currentVoice == null`; otherwise synthesizes `TTS_PREVIEW_SAMPLE` with `currentVoice`.
   - No Engine row, no Manage Engines link, no rate slider.

9. **[MUST]** Add l10n keys under `voiceAndSpeech` namespace in `src/locales/en.json`: section titles, System header label, `notSet`, Preview button label, Supertonic install-CTA placeholder copy, row accessibility labels.

### Non-Functional
- **Performance**: `PlayButton` must not cause sibling messages to re-render when playback state changes. Observer wraps the button only.
- **Accessibility**: all tap targets ≥44pt. Each split-chip half has its own `accessibilityLabel`.

## Acceptance Criteria

- [ ] On a ≥6 GiB device, tapping a per-message play button with `currentVoice == null` opens the setup sheet and plays no audio.
- [ ] Selecting a System voice in the setup sheet dismisses the sheet, populates `currentVoice`, and renders the full split-chip form with the voice name.
- [ ] Tapping the play button with a System voice chosen → audio plays via System TTS. Tap again → stops.
- [ ] With `autoSpeakEnabled=true` and a System voice chosen, a newly completed assistant message auto-plays once; re-renders do not re-trigger.
- [ ] Input-bar split chip has two independently tappable halves, each ≥44pt wide, separated by a visible vertical divider.
- [ ] Voice name label truncates: full → 3 chars → icon-only as chip width shrinks.
- [ ] Speaker icon states render: outline (OFF), filled (ON idle), waveform (playing).
- [ ] Setup sheet renders Supertonic section FIRST (even though disabled/placeholder) and System section BELOW with the honest label.
- [ ] Supertonic voice rows and Preview buttons are visibly disabled / non-interactive in v1.1.
- [ ] On a <6 GiB device (mocked): no play button, no VoiceChip, no Settings Voice & Speech section.
- [ ] Single-word / emoji-only assistant messages have no play button.
- [ ] All unit tests pass; Jest coverage for new files ≥ 60%.
- [ ] iOS and Android Release builds succeed.
- [ ] Visual capture spec passes on iOS simulator.
