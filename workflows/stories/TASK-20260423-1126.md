### Background

PocketPal supports multimodal (vision) models via HuggingFace-downloaded projection (mmproj) models. The existing flow adds projection models as first-class `Model` entries with `modelType: PROJECTION` and links them to parent LLMs via `compatibleProjectionModels` and `defaultProjectionModel`. However, there is no way to attach a **local** mmproj file from the filesystem. Users who sideload GGUF vision models (or even HF-downloaded LLMs that happen to be multimodal) cannot use vision features because there is no UI to attach a local projection file.

### Current State

### Target State

1. Users can attach a local mmproj file to **any** LLM (local or HF) via ModelSettingsSheet or ModelCard overflow.
2. The mmproj file is copied into `${DocumentDirectoryPath}/models/local/projection/`, validated via `loadLlamaModelInfo` (must have `general.architecture === 'clip'`), and added as a `Model` entry with `origin: LOCAL, modelType: PROJECTION`.
3. After attach, the parent LLM gets `supportsMultimodal = true`, the projection is linked via `compatibleProjectionModels` and `defaultProjectionModel`, and the existing `ProjectionModelSelector` renders.
4. If the parent LLM is currently active, the user is prompted to reload the context with the new projection model (same reload Alert pattern as `ProjectionModelSelector.tsx:81-102`).
5. If local projections already exist in the store, user sees a bottom sheet with "Use existing" list + "Pick file..." option. If none exist, goes straight to document picker.
6. A compatibility warning is shown in the attach flow, informing the user to ensure the projection model is compatible with their LLM.
7. Multimodal init errors are surfaced to the user via the existing `uiStore.chatWarning` mechanism.
8. Deleting a projection model cleans up stale references (`compatibleProjectionModels`, `defaultProjectionModel`) on dependent models.

```typescript
// registerLocalProjectionModel — receives already-copied path (like addLocalModel)
registerLocalProjectionModel = async (permanentPath: string, parentModelId: string): Promise<Model> => {
  const filename = permanentPath.split('/').pop();
  if (!filename) throw new Error('Invalid file path');

  // Validate: must be clip architecture
  try {
    const modelInfo = await loadLlamaModelInfo(permanentPath);
    const arch = (modelInfo as any)?.['general.architecture'];
    if (arch !== 'clip') {
      await RNFS.unlink(permanentPath);
      throw new Error(`Not a projection model (architecture: ${arch || 'unknown'}). Expected: clip`);
    }
  } catch (e) {
    if (await RNFS.exists(permanentPath)) await RNFS.unlink(permanentPath);
    throw e;
  }

  const stat = await RNFS.stat(permanentPath);
  const defaultSettings = getLocalModelDefaultSettings();
  const model: Model = {
    id: uuidv4(),
    author: '',
    name: filename,
    size: Number(stat.size) || 0,
    params: 0,
    isDownloaded: true,
    downloadUrl: '',
    hfUrl: '',
    progress: 0,
    filename,
    fullPath: permanentPath,
    isLocal: true,
    origin: ModelOrigin.LOCAL,
    modelType: ModelType.PROJECTION,
    defaultChatTemplate: {...defaultSettings.chatTemplate},
    chatTemplate: {...defaultSettings.chatTemplate},
    defaultStopWords: [...(defaultSettings?.completionParams?.stop || [])],
    stopWords: [...(defaultSettings?.completionParams?.stop || [])],
    defaultCompletionSettings: defaultSettings.completionParams,
    completionSettings: {...defaultSettings.completionParams},
  };

  runInAction(() => {
    this.models.push(model);
  });

  this.linkProjectionToModel(model.id, parentModelId);
  return model;
};

// linkProjectionToModel
linkProjectionToModel = (projectionId: string, parentModelId: string) => {
  const parent = this.models.find(m => m.id === parentModelId);
  if (!parent) throw new Error('Parent model not found');

  runInAction(() => {
    parent.supportsMultimodal = true;
    if (!parent.compatibleProjectionModels) {
      parent.compatibleProjectionModels = [];
    }
    if (!parent.compatibleProjectionModels.includes(projectionId)) {
      parent.compatibleProjectionModels.push(projectionId);
    }
    parent.defaultProjectionModel = projectionId;
  });
};

// unlinkProjectionFromModel — removes a projection reference without deleting the file
unlinkProjectionFromModel = (projectionId: string, parentModelId: string) => {
  const parent = this.models.find(m => m.id === parentModelId);
  if (!parent) return;

  runInAction(() => {
    if (parent.compatibleProjectionModels) {
      parent.compatibleProjectionModels = parent.compatibleProjectionModels.filter(
        id => id !== projectionId,
      );
    }
    if (parent.defaultProjectionModel === projectionId) {
      parent.defaultProjectionModel =
        parent.compatibleProjectionModels?.[0] ?? undefined;
    }
  });
};

// Update multimodal init catch block (line 1614-1620)
} catch (error) {
  console.error('Error initializing multimodal support:', error);
  runInAction(() => {
    this.isMultimodalActive = false;
    this.activeProjectionModelId = undefined;
  });
  uiStore.setChatWarning({
    message: l10n.models.multimodal.multimodalInitFailed,
    shouldShow: true,
  });
}
```

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| `loadLlamaModelInfo` may fail on malformed files | Medium | Low | Catch block already exists; we clean up copied file on any error |
| iOS security-scoped URL expires before copy completes | Low | Medium | Same risk as existing local model flow; copy happens immediately after pick |
| User copies large mmproj file twice (via "Pick file" instead of "Use existing") | Low | Low | Accepted tradeoff — no content hashing (YAGNI). "Use existing" flow mitigates for power users |
| MobX persistence may not serialize new fields correctly | Low | Medium | All new fields are standard types (string, boolean, array). Tested via existing persistence mechanism |
| uiStore import in ModelStore catch block creates coupling | Low | Low | ModelStore already imports from other stores in similar patterns; this is a single-line import for error surfacing |
| Incompatible mmproj attached to wrong LLM | Medium | Low | No reliable programmatic validation exists (even HF uses filename heuristics). Compatibility warning text shown. `initMultimodal` failure surfaces via `chatWarning`. User is the compatibility oracle |
| Stale projection IDs in existing HF models (pre-existing bug) | Low | Low | Our `unlinkProjectionFromModel` + deletion cleanup fixes this for all models going forward, not just local |
| Active model context not reloaded after attach | Medium | High | Explicit reload check after attach/link, following ProjectionModelSelector pattern. Test case added |

## Open Questions

### For Human
- [ ] Should the "Attach projection model..." button also be visible when a model already has a working projection (to allow switching/adding alternatives)? Current design: hidden when `defaultProjectionModel` is set AND projection is available, since user can use ProjectionModelSelector to manage existing projections.

### Resolved
- File picker type: Reuse same `types.allFiles` / `public.data` as existing local model flow
- Storage location: `models/local/projection/` subdirectory (parallel to `models/local/` for LLMs)
- Validation: `loadLlamaModelInfo` + check `general.architecture === 'clip'`
- Error surfacing: Use existing `uiStore.chatWarning` (no new observable needed)
- Double-copy concern: `pickAndCopyLocalGGUF` handles copy, `registerLocalProjectionModel` receives permanent path (no copy)
- Button visibility for failed HF projections: Show button when `projectionModelStatus.state === 'missing'`
- Compatibility validation: User is the compatibility oracle — no reliable programmatic way to verify. Warning text + `initMultimodal` error surfacing is sufficient
- Active model reload: Follow `ProjectionModelSelector.tsx:74-104` Alert pattern after attach/link
- Deletion cleanup: `unlinkProjectionFromModel` cleans stale IDs; called from `deleteModel` for PROJECTION types
- Picker error handling: Follow `importUtils.ts:66-84` pattern for `IN_PROGRESS`, `OPERATION_CANCELED`, `UNABLE_TO_OPEN_FILE_TYPE`
