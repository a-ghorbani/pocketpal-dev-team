### Background

PocketPal's localization is in a single monolithic TypeScript file `src/utils/l10n.ts` (3,970 lines) containing all translations for 3 languages (en, ja, zh) across 19 top-level sections. This creates several problems:

1. **Weblate incompatibility**: The Weblate translation platform expects JSON files, not TypeScript objects with arrow functions
2. **Not file-based**: All 3 languages live in one monolithic file, making Weblate sync and per-language PRs impossible (note: the current TS object IS type-safe — missing keys in `ja`/`zh` cause compile errors today; we must preserve this when moving to JSON)
3. **Manual string interpolation**: ~28 call sites use chained `.replace()` calls with mixed `{single}` and `{{double}}` brace formats, which are error-prone and untyped
4. **Broken Weblate sync**: `scripts/sync-weblate.js` has an `uploadSourceFile()` that never sends the HTTP request, and `downloadTranslations()` uses the wrong API path
5. **No CI validation**: Nothing prevents broken JSON or missing translation keys from being merged

### Step 2: Create `src/locales/index.ts` with `l10n` export and `t()` helper
**Files**: `src/locales/index.ts`
**Status**: `PENDING`

**Change**:
- [ ] Create `src/locales/index.ts` that:
  - Imports the 3 JSON files and `Translations` type
  - Uses `_.merge` from lodash (already a dependency) to overlay each language onto `en`
  - Exports `l10n` with the shape `{ en: Translations, ja: Translations, zh: Translations }`

**Code Guidance**:
```typescript
// src/locales/index.ts
import _ from 'lodash';

import enData from './en.json';
import jaData from './ja.json';
import zhData from './zh.json';

import type {Translations} from './types';

// _.merge overlays language-specific values onto en, falling back to en for missing keys.
// Using {} as first arg prevents mutation of enData.
const en: Translations = enData;
const ja: Translations = _.merge({}, enData, jaData);
const zh: Translations = _.merge({}, enData, zhData);

export const l10n = {en, ja, zh} as const;

/**
 * Typed interpolation helper.
 * Replaces all {{placeholder}} patterns in the template with values from the params object.
 *
 * @example
 * t(l10n.en.storage.lowStorage, { modelSize: '4 GB', freeSpace: '2 GB' })
 * // => 'Storage low! Model 4 GB > 2 GB free'
 */
export function t(
  template: string,
  params: Record<string, string | number>,
): string {
  return template.replace(
    /\{\{(\w+)\}\}/g,
    (_, key) => String(params[key] ?? `{{${key}}}`),
  );
}
```

**Why `_.merge` instead of the existing `deepMerge`**:
- `deepMerge` (at `src/utils/index.ts:366-384`) has WRONG semantics: it only sets keys if they're MISSING in target. So `deepMerge(clone(en), ja)` would keep all English values and ignore Japanese translations.
- `_.merge` has correct overlay semantics: `ja` values overwrite `en` values where they exist; `en` fills in where `ja` is missing.
- Lodash is already imported in `src/utils/index.ts` — no new dependency.

### Step 6: Add CI guardrails and Weblate lifecycle docs
**Files**: `scripts/validate-l10n.js`, `.github/workflows/ci.yml`, `.github/workflows/l10n-upload.yml`, `package.json`

- [ ] Create `scripts/validate-l10n.js` (plain JavaScript — no ts-node dependency needed) that:
  1. Validates all JSON files parse correctly
  2. Compares ja.json and zh.json keys against en.json (reports missing/extra keys as warnings)
  3. Validates placeholder consistency: any `{{key}}` in en must exist in ja/zh for same path (errors)
  4. Exits with non-zero code on validation failure

  ```javascript
  #!/usr/bin/env node
  const fs = require('fs');
  const path = require('path');

  const LOCALES_DIR = path.join(__dirname, '../src/locales');
  const EN_PATH = path.join(LOCALES_DIR, 'en.json');

  function getKeys(obj, prefix = '') {
    const keys = [];
    for (const key in obj) {
      const fullKey = prefix ? `${prefix}.${key}` : key;
      if (typeof obj[key] === 'object' && obj[key] !== null) {
        keys.push(...getKeys(obj[key], fullKey));
      } else {
        keys.push(fullKey);
      }
    }
    return keys;
  }

  function getPlaceholders(str) {
    const matches = str.match(/\{\{(\w+)\}\}/g) || [];
    return matches.sort();
  }

  function getValueAtPath(obj, keyPath) {
    return keyPath.split('.').reduce((o, k) => o && o[k], obj);
  }

  let errors = 0;

  // 1. Validate JSON parsing
  let en;
  try {
    en = JSON.parse(fs.readFileSync(EN_PATH, 'utf-8'));
    console.log('en.json: valid JSON');
  } catch (e) {
    console.error('en.json: INVALID JSON:', e);
    process.exit(1);
  }

  const enKeys = getKeys(en);
  console.log(`en.json: ${enKeys.length} keys`);

  for (const lang of ['ja', 'zh']) {
    const langPath = path.join(LOCALES_DIR, `${lang}.json`);
    let langData;

    try {
      langData = JSON.parse(fs.readFileSync(langPath, 'utf-8'));
      console.log(`${lang}.json: valid JSON`);
    } catch (e) {
      console.error(`${lang}.json: INVALID JSON:`, e);
      errors++;
      continue;
    }

    const langKeys = getKeys(langData);

    // 2. Check missing keys (warnings, not errors — fallback handles them)
    const missingKeys = enKeys.filter(k => !langKeys.includes(k));
    if (missingKeys.length > 0) {
      console.warn(`${lang}.json: ${missingKeys.length} missing keys (will fall back to English)`);
    }

    // 3. Check placeholder consistency (errors — mismatched placeholders are bugs)
    for (const key of langKeys) {
      const enValue = getValueAtPath(en, key);
      const langValue = getValueAtPath(langData, key);

      if (typeof enValue === 'string' && typeof langValue === 'string') {
        const enPlaceholders = getPlaceholders(enValue);
        const langPlaceholders = getPlaceholders(langValue);

        if (JSON.stringify(enPlaceholders) !== JSON.stringify(langPlaceholders)) {
          console.error(
            `${lang}.json: placeholder mismatch at "${key}": ` +
            `en has [${enPlaceholders.join(', ')}] but ${lang} has [${langPlaceholders.join(', ')}]`
          );
          errors++;
        }
      }
    }
  }

  if (errors > 0) {
    console.error(`\nValidation failed with ${errors} error(s)`);
    process.exit(1);
  } else {
    console.log('\nAll l10n files valid');
  }
  ```
