## Context

### Background
Issue #657 requests enabling Qualcomm's `cl_qcom_large_buffer` OpenCL extension on Adreno A7X/A8X GPUs. Without this extension, the OpenCL backend hits a ~1 GB `CL_DEVICE_MAX_MEM_ALLOC_SIZE` cap per allocation, forcing larger model weights or long-context KV caches off-GPU. Enabling large buffers allows more of the model to stay on GPU on flagship Snapdragon Android devices, improving throughput and unlocking larger models.

Upstream llama.cpp landed the feature in [ggml-org/llama.cpp#20997](https://github.com/ggml-org/llama.cpp/pull/20997) (merged 2026-03-26). llama.rn synced it as b8547 (2026-03-27) and the feature is present in our pinned `0.12.0-rc.9`. Per jhen0409 in mybigday/llama.rn#328, llama.rn uses the `LM_` prefix for all `GGML_OPENCL_*` env vars (consistent with existing `LM_GGML_OPENCL_PLATFORM` / `LM_GGML_OPENCL_DEVICE`).

Native gating in `ggml-opencl.cpp` (confirmed in `node_modules/llama.rn/cpp/ggml-opencl/ggml-opencl.cpp:3244-3254`):
```cpp
backend_ctx->adreno_use_large_buffer = getenv("LM_GGML_OPENCL_ADRENO_USE_LARGE_BUFFER") != nullptr &&
                                       backend_ctx->gpu_family == GPU_FAMILY::ADRENO;
if (backend_ctx->adreno_use_large_buffer) {
    if (!backend_ctx->adreno_has_large_buffer) {
        LM_GGML_LOG_INFO("lm_ggml_opencl: Adreno large buffer requested but not supported by driver, will use regular buffer\n");
        backend_ctx->adreno_use_large_buffer = false;
    } else {
        LM_GGML_LOG_INFO("lm_ggml_opencl: Adreno large buffer enabled\n");
    }
}
```
The native layer checks: (a) env var presence, (b) GPU family == ADRENO, (c) `cl_qcom_large_buffer` extension available, with graceful fallback. This makes Kotlin-side device detection redundant complexity.

### Current State
- `android/app/src/main/java/com/pocketpalai/MainApplication.kt:44-51` — `onCreate()` runs `super.onCreate()` then `SoLoader.init(this, OpenSourceMergedSoMapping)`. No environment variables are set before native library load.
- `grep -r "LM_GGML_OPENCL\|setenv" android/` — NO existing matches. This is the first such env init in the repo.
- llama.rn native `.so` libraries load when `SoLoader.init` is called (or later when a React Native module referencing them is instantiated). Env vars must be set BEFORE the OpenCL backend initializes, which happens lazily on first model load. Setting in `onCreate` before `SoLoader.init` is the safest point — this is standard Android practice for native-level env config.
- iOS path is unaffected: PocketPal iOS uses Metal, not OpenCL. `GGML_USE_METAL` is the iOS backend.

### Target State
- On every Android app cold start, `LM_GGML_OPENCL_ADRENO_USE_LARGE_BUFFER=1` is set in the process environment before native libraries load.
- On Adreno A7X/A8X (Snapdragon 8 Gen 2+, 8 Elite, etc.) with `cl_qcom_large_buffer` support, the native OpenCL backend enables large buffers and logs `lm_ggml_opencl: Adreno large buffer enabled`.
- On all other devices (non-Adreno, older Adreno without the extension, or CPU-only builds), the native layer no-ops gracefully — the env var has no observable effect.
- iOS behavior is unchanged.

import android.system.Os
import com.facebook.react.PackageList

class MainApplication : Application(), ReactApplication {

  // ... reactNativeHost unchanged ...

  override fun onCreate() {
    super.onCreate()
    // Enable Adreno large buffer support on Qualcomm A7X/A8X GPUs.
    // The OpenCL backend in llama.rn self-gates on GPU family and the
    // cl_qcom_large_buffer extension — this is a no-op on non-Adreno devices.
    // Must be set before SoLoader.init so the native library picks it up.

}

Notes for the implementer:
- The comment is load-bearing for future maintainers — keep it. A drive-by reader seeing a bare `setenv` with no context would be confused.
- `overwrite = true` (third arg) ensures the value is written even if some upstream SDK pre-sets it. Cheap insurance.
- Do NOT wrap in a try/catch. `Os.setenv` throws `ErrnoException` only for invalid names or oversize values — neither applies here. Swallowing would hide real bugs.
- Do NOT add a `BuildConfig.DEBUG` check or any conditional — we want this on for all users on Adreno devices.
- Do NOT move `SoLoader.init` or rearrange the method. Only insert the two new lines (comment + setenv).
