### Background
Users report that advanced settings (specifically CPU thread count) reset to defaults on every app restart. A user on a Poco F3 (8 cores) sets threads to 4 but after restart they revert to 6 (which is `Math.floor(8 * 0.8)`). This affects all persisted `contextInitParams` settings because `initializeThreadCount()` unconditionally overwrites `n_threads` on every startup.

GitHub issue #582: https://github.com/a-ghorbani/pocketpal-ai/issues/582

### Current State

**`src/store/ModelStore.ts` constructor (lines 136-155):**
```typescript
constructor() {
    makeAutoObservable(this, {activeModel: computed});
    this.initializeThreadCount();  // <-- Called BEFORE persistence loads
    makePersistable(this, {
      name: 'ModelStore',
      properties: [
        'models',
        'version',
        'useAutoRelease',
        'contextInitParams',  // <-- This includes n_threads
        // ...
      ],
      storage: AsyncStorage,
    }).then(async () => {
      this.initializeStore();
    });
    // ...
}
```

**`initializeThreadCount()` (lines 206-229):**
```typescript
private async initializeThreadCount() {
    try {
      const cores = await getCpuCoreCount();
      this.max_threads = cores;

      const threads = await getRecommendedThreadCount();
      runInAction(() => {
        this.contextInitParams = {
          ...this.contextInitParams,
          n_threads: threads,  // <-- Unconditionally overwrites persisted value
        };
      });
    } catch (error) {
      // fallback to 4
    }
}
```

**The race condition:**
1. Constructor calls `initializeThreadCount()` (async, not awaited)
2. Constructor calls `makePersistable()` (async, returns promise)
3. Both run concurrently. `makePersistable` restores persisted `contextInitParams` from AsyncStorage (including user's saved `n_threads`)
4. `initializeThreadCount()` resolves and unconditionally overwrites `n_threads` with `getRecommendedThreadCount()`, destroying the user's saved value

Even if hydration wins the race, `initializeThreadCount` will eventually resolve and overwrite the value. The key issue is **unconditional** overwrite -- it should only set the recommended value on first launch.

### Target State
- `max_threads` should always be detected on startup (it reflects hardware, not a user preference)
- `n_threads` should only be set to the recommended value on **first launch** (when no persisted data exists)
- After persistence hydration, the user's saved `n_threads` value must be preserved
- The thread count initialization must happen **after** `makePersistable` resolves, not concurrently

The `initializeThreadCount` method should change from:
```typescript
private async initializeThreadCount() {
    try {
      const cores = await getCpuCoreCount();
      this.max_threads = cores;

      const threads = await getRecommendedThreadCount();
      runInAction(() => {
        this.contextInitParams = {

    } catch (error) {
      console.error('Failed to initialize thread count:', error);
      runInAction(() => {

        this.contextInitParams = {
          ...this.contextInitParams,
          n_threads: 4,
        };
      });
    }

```

To:
```typescript
private async initializeThreadCount() {
    try {
      const cores = await getCpuCoreCount();
      runInAction(() => {
        this.max_threads = cores;
      });

      // Only set n_threads to recommended value on first launch
      // (when n_threads is still the hardcoded default of 4 from createDefaultContextInitParams)
      // After hydration, if user has customized n_threads, it will already be loaded
      const isFirstLaunch = this.contextInitParams.n_threads === createDefaultContextInitParams().n_threads;
      if (isFirstLaunch) {
        const threads = await getRecommendedThreadCount();
        runInAction(() => {
          this.contextInitParams = {
            ...this.contextInitParams,
            n_threads: threads,
          };
        });
      }
    } catch (error) {
      console.error('Failed to initialize thread count:', error);
      runInAction(() => {
        this.max_threads = 4;
      });
    }
}
```

**IMPORTANT DESIGN NOTE**: The "first launch" detection using `n_threads === 4` (the hardcoded default from `createDefaultContextInitParams`) has a subtle edge case: if a user explicitly sets n_threads to 4, then on next restart it would look like a first launch and overwrite with recommended. However, this is actually acceptable because:
1. If the device has <= 4 cores, recommended = 4 (same value, no visible change)
2. If the device has > 4 cores, recommended = `floor(cores * 0.8)` which is always > 4, so the user's explicit choice of 4 would be overwritten

A more robust approach would be to track whether thread count has ever been persisted. Since `contextInitParams` is persisted as a whole and hydration restores the entire object, we can use a different signal. The cleanest approach: **check if `max_threads` has been set to a non-default value**. But `max_threads` is not persisted.

**Alternative (RECOMMENDED) approach**: Instead of trying to detect first launch, simply **never overwrite n_threads if persistence has loaded data**. Since `initializeThreadCount` now runs AFTER `makePersistable` resolves, we know hydration is complete. The key insight is:

- If this is a fresh install, `makePersistable` finds nothing in AsyncStorage, so `contextInitParams` stays at defaults (n_threads = 4)
- If there is persisted data, `contextInitParams.n_threads` will be whatever the user set

We need a way to distinguish "default because fresh" from "4 because user chose 4". The simplest solution: **add a `_threadCountInitialized` flag** (not persisted) that is set after first initialization. But this adds complexity.

**SIMPLEST CORRECT APPROACH**: Use the `version` field from the persisted store. If `this.version` is defined after hydration, the store has been persisted before (not a fresh install). If `this.version` is undefined, this is a fresh install.

```typescript
private async initializeThreadCount() {
    try {
      const cores = await getCpuCoreCount();
      runInAction(() => {
        this.max_threads = cores;
      });

      // Only set recommended thread count on first launch.
      // After hydration, this.version is set if the store was previously persisted.
      // On fresh install, this.version is undefined (default).
      const isFirstLaunch = this.version === undefined;
      if (isFirstLaunch) {
        const threads = await getRecommendedThreadCount();
        runInAction(() => {
          this.contextInitParams = {
            ...this.contextInitParams,
            n_threads: threads,
          };
        });
      }
    } catch (error) {
      console.error('Failed to initialize thread count:', error);
      runInAction(() => {
        this.max_threads = 4;
      });
    }
}
```

This works because:
- `version` is in the persisted properties list (line 143)
- `version` defaults to `undefined` (line 72)
- On first launch, `makePersistable` loads nothing, `version` stays `undefined`
- After `initializeStore` runs, `version` gets set to `MODEL_LIST_VERSION` (line 447)
- On subsequent launches, `version` is loaded from AsyncStorage and is a number

**Edge case verification**: What if a user had a previous version installed (where version was already set) but never changed n_threads? Their n_threads would be whatever `initializeThreadCount` set previously (the recommended count). After this fix, it would stay at that value because `version !== undefined`. This is correct -- the recommended count is the appropriate value for users who never changed it.

Since `initializeThreadCount` is private, we need to test it indirectly. The method is called inside the `makePersistable.then()` callback. Since `makePersistable` is mocked to resolve immediately (see `__mocks__/external/mobx-persist-store.js`), the constructor will trigger the `.then()` callback on the next microtask.

However, since the test file imports the singleton `modelStore` (which is already constructed when the module loads), the tests will need to either:
1. Access the method via bracket notation: `(modelStore as any).initializeThreadCount()`
2. Or test the behavior after construction by checking the state

The implementer should use approach (1) for direct testing of the method behavior, setting up `modelStore.version` to simulate first launch vs subsequent launch before calling the method:

```typescript
describe('initializeThreadCount', () => {
  beforeEach(() => {
    jest.clearAllMocks();
  });

  it('should always update max_threads from hardware', async () => {
    (getCpuCoreCount as jest.Mock).mockResolvedValue(10);
    (getRecommendedThreadCount as jest.Mock).mockResolvedValue(8);

    await (modelStore as any).initializeThreadCount();

    expect(modelStore.max_threads).toBe(10);
  });

  it('should set recommended n_threads on first launch', async () => {
    modelStore.version = undefined; // Simulate first launch
    (getCpuCoreCount as jest.Mock).mockResolvedValue(8);
    (getRecommendedThreadCount as jest.Mock).mockResolvedValue(6);

    await (modelStore as any).initializeThreadCount();

    expect(modelStore.contextInitParams.n_threads).toBe(6);
  });

  it('should preserve user n_threads on subsequent launches', async () => {
    modelStore.version = 1; // Simulate persisted store
    runInAction(() => {
      modelStore.contextInitParams = {
        ...modelStore.contextInitParams,
        n_threads: 4, // User explicitly set to 4
      };
    });
    (getCpuCoreCount as jest.Mock).mockResolvedValue(8);
    (getRecommendedThreadCount as jest.Mock).mockResolvedValue(6);

    await (modelStore as any).initializeThreadCount();

    expect(modelStore.contextInitParams.n_threads).toBe(4); // Preserved!
    expect(modelStore.max_threads).toBe(8); // Still updated
  });

  it('should fallback max_threads to 4 on error without touching n_threads', async () => {
    modelStore.version = 1;
    runInAction(() => {
      modelStore.contextInitParams = {
        ...modelStore.contextInitParams,
        n_threads: 3,
      };
    });
    (getCpuCoreCount as jest.Mock).mockRejectedValue(new Error('fail'));

    await (modelStore as any).initializeThreadCount();

    expect(modelStore.max_threads).toBe(4);
    expect(modelStore.contextInitParams.n_threads).toBe(3); // Untouched
  });
});
```
