### Background
PocketPal runs LLMs on-device which are memory-intensive. We need automated memory profiling to catch regressions before they ship. Currently there is no way to track memory at key app checkpoints (launch, model load, chat, model unload). This pipeline will establish versioned baselines and detect regressions via comparison.

### Current State
- `ios/PocketPal/HardwareInfoModule.mm` -- exposes `getCPUInfo`, `getGPUInfo`, `getAvailableMemory` (uses `os_proc_available_memory()`)
- `android/app/src/main/java/com/pocketpalai/HardwareInfoModule.kt` -- exposes same three methods; `getAvailableMemory` uses `ActivityManager.getMemoryInfo()`
- `src/specs/NativeHardwareInfo.ts` -- TurboModule spec with `getCPUInfo()`, `getGPUInfo()`, `getChipset?()`, `getAvailableMemory()`
- `src/utils/deviceCapabilities.ts` -- JS wrappers around NativeHardwareInfo
- E2E infrastructure: Appium + WebDriverIO with page object model (`e2e/pages/`), model fixtures (`e2e/fixtures/models.ts`), helper functions (`e2e/helpers/model-actions.ts`), unified runner (`e2e/scripts/run-e2e.ts`)
- No memory profiling exists anywhere in the codebase
- `HermesInternal` is not currently used anywhere in `src/`
- The app already uses `RNFS.writeFile` and `RNFS.DocumentDirectoryPath` extensively (e.g., `ChatSessionRepository.ts`, `DownloadManager.ts`)
- Deep link infrastructure (`DeepLinkService.ts`, `DeepLinkModule`) is iOS-only -- no Android support

### Target State
1. **Native modules** expose `getMemoryProfile()` returning platform-specific memory metrics and `writeMemorySnapshot(label)` which collects memory + writes a JSON snapshot to a known file path on disk
2. **TurboModule spec** updated with both method signatures
3. **JS helper** `src/utils/memoryProfile.ts` provides a callable `takeMemorySnapshot(label)` that invokes the native `writeMemorySnapshot` and also appends Hermes heap stats
4. **Hidden trigger component** `src/components/MemorySnapshotTrigger.tsx` renders a hidden `View` with `testID="memory-snapshot-trigger"` that E2E taps to trigger snapshots. A sibling hidden `TextInput` with `testID="memory-snapshot-label"` receives the label from E2E before the tap
5. **E2E spec** `e2e/specs/memory-profile.spec.ts` navigates through 7 checkpoints. At each checkpoint it sets the label in the hidden input, taps the trigger element, then reads the accumulated snapshots file from the device filesystem
6. **Comparison script** `scripts/memory-compare.ts` loads two JSON reports and flags regressions using absolute thresholds
7. **Shell wrapper** `scripts/memory-profile.sh` orchestrates build, run, and compare

### Architecture: Native Module as Single Source of Truth

The core insight: **the native module already has the memory data we need**. Rather than using unreliable external shell commands (`footprint` on iOS, `dumpsys meminfo` on Android), the E2E pipeline triggers the app to collect and write its own memory data.

**Data flow:**
```
E2E navigates to checkpoint
  → E2E sets label in hidden TextInput via setValue()
  → E2E taps hidden View with testID="memory-snapshot-trigger"
  → App's onPress handler calls takeMemorySnapshot(label)
  → takeMemorySnapshot() calls NativeHardwareInfo.writeMemorySnapshot(label)
  → Native module collects memory metrics + writes JSON to DocumentDirectoryPath/memory-snapshots.json
  → After all checkpoints, E2E reads the file from device
  → E2E writes canonical report to OUTPUT_DIR
```

**How E2E triggers snapshots:** The app mounts a hidden `MemorySnapshotTrigger` component (always present, zero visual footprint). This component renders a hidden `TextInput` (for the label) and a hidden `View` (tap target). The E2E spec uses `driver.setValue()` on the input to set the checkpoint label, then taps the trigger view. The component's `onPress` handler reads the current label and calls `takeMemorySnapshot(label)`. This approach works identically on iOS and Android with zero native infrastructure beyond the existing React Native accessibility/testID system.

**How E2E reads the file:**
- iOS simulator: `execSync('xcrun simctl get_app_container booted ai.pocketpal data')` returns the data container path, then read `<container>/Documents/memory-snapshots.json` directly from the host filesystem
- Android: `adb pull /data/data/com.pocketpalai/files/memory-snapshots.json <local-path>` via `execSync`
- Both approaches use host-side commands that are well-established and reliable

```objc
#import <mach/mach.h>

RCT_EXPORT_METHOD(getMemoryProfile:(RCTPromiseResolveBlock)resolve
                  rejecter:(RCTPromiseRejectBlock)reject)
{
  @try {
    task_vm_info_data_t vmInfo;
    mach_msg_type_number_t count = TASK_VM_INFO_COUNT;
    kern_return_t result = task_info(mach_task_self(), TASK_VM_INFO,
                                     (task_info_t)&vmInfo, &count);

    uint64_t physFootprint = 0;
    if (result == KERN_SUCCESS) {
      physFootprint = vmInfo.phys_footprint;
    }

    uint64_t availableMemory = os_proc_available_memory();

    NSDictionary *profile = @{
      @"phys_footprint": @(physFootprint),
      @"available_memory": @(availableMemory),
    };

    resolve(profile);
  } @catch (NSException *exception) {
    reject(@"error_getting_memory_profile", @"Could not retrieve memory profile", nil);
  }
}
```

**Code Guidance (iOS -- writeMemorySnapshot)**:
```objc
RCT_EXPORT_METHOD(writeMemorySnapshot:(NSString *)label
                  resolver:(RCTPromiseResolveBlock)resolve
                  rejecter:(RCTPromiseRejectBlock)reject)
{
  @try {
    // Collect memory metrics (same as getMemoryProfile)
    task_vm_info_data_t vmInfo;
    mach_msg_type_number_t count = TASK_VM_INFO_COUNT;
    kern_return_t result = task_info(mach_task_self(), TASK_VM_INFO,
                                     (task_info_t)&vmInfo, &count);
    uint64_t physFootprint = (result == KERN_SUCCESS) ? vmInfo.phys_footprint : 0;
    uint64_t availableMemory = os_proc_available_memory();

    NSDictionary *snapshot = @{
      @"label": label,
      @"timestamp": [[NSISO8601DateFormatter new] stringFromDate:[NSDate date]],
      @"native": @{
        @"phys_footprint": @(physFootprint),
        @"available_memory": @(availableMemory),
      },
    };

    // Read existing snapshots, append, write back
    NSString *docsDir = NSSearchPathForDirectoriesInDomains(
      NSDocumentDirectory, NSUserDomainMask, YES).firstObject;
    NSString *filePath = [docsDir stringByAppendingPathComponent:@"memory-snapshots.json"];

    NSMutableArray *snapshots = [NSMutableArray array];
    if ([[NSFileManager defaultManager] fileExistsAtPath:filePath]) {
      NSData *data = [NSData dataWithContentsOfFile:filePath];
      NSArray *existing = [NSJSONSerialization JSONObjectWithData:data options:0 error:nil];
      if (existing) [snapshots addObjectsFromArray:existing];
    }
    [snapshots addObject:snapshot];

    NSData *jsonData = [NSJSONSerialization dataWithJSONObject:snapshots
                                                      options:NSJSONWritingPrettyPrinted
                                                        error:nil];
    [jsonData writeToFile:filePath atomically:YES];

    resolve(snapshot);
  } @catch (NSException *exception) {
    reject(@"error_writing_memory_snapshot", @"Could not write memory snapshot", nil);
  }
}
```

```kotlin
import android.os.Debug

override fun getMemoryProfile(promise: Promise) {
    try {
        val profile = Arguments.createMap()

        // PSS Total (Debug.getPss() returns KB)
        val pssKb = Debug.getPss()
        profile.putDouble("pss_total", pssKb * 1024.0)

        // Native heap allocated (bytes)
        profile.putDouble("native_heap_allocated", Debug.getNativeHeapAllocatedSize().toDouble())

        // Available memory (same as getAvailableMemory)
        val activityManager = reactApplicationContext
            .getSystemService(Context.ACTIVITY_SERVICE) as ActivityManager
        val memInfo = ActivityManager.MemoryInfo()
        activityManager.getMemoryInfo(memInfo)
        profile.putDouble("available_memory", memInfo.availMem.toDouble())

        promise.resolve(profile)
    } catch (e: Exception) {
        promise.reject("ERROR", e.message)
    }
}
```

**Code Guidance (Android -- writeMemorySnapshot)**:
```kotlin
override fun writeMemorySnapshot(label: String, promise: Promise) {
    try {
        // Collect memory metrics
        val pssKb = Debug.getPss()
        val nativeHeap = Debug.getNativeHeapAllocatedSize()
        val activityManager = reactApplicationContext
            .getSystemService(Context.ACTIVITY_SERVICE) as ActivityManager
        val memInfo = ActivityManager.MemoryInfo()
        activityManager.getMemoryInfo(memInfo)

        val snapshot = JSONObject().apply {
            put("label", label)
            put("timestamp", java.time.Instant.now().toString())
            put("native", JSONObject().apply {
                put("pss_total", pssKb * 1024.0)
                put("native_heap_allocated", nativeHeap.toDouble())
                put("available_memory", memInfo.availMem.toDouble())
            })
        }

        // Read existing, append, write back
        val file = File(reactApplicationContext.filesDir, "memory-snapshots.json")
        val snapshots = if (file.exists()) {
            JSONArray(file.readText())
        } else {
            JSONArray()
        }
        snapshots.put(snapshot)
        file.writeText(snapshots.toString(2))

        promise.resolve(Arguments.createMap().apply {
            putString("label", label)
            putString("status", "written")
        })
    } catch (e: Exception) {
        promise.reject("ERROR", e.message)
    }
}
```

```typescript
  native: {

    pss_total?: number;

/**
 * Trigger a memory snapshot in the app via hidden testID element.
 * Works on both iOS and Android -- no deep link infrastructure needed.
 */
export async function triggerSnapshot(label: string): Promise<void> {
  // Set the label in the hidden TextInput
  const labelInput = await driver.$('~memory-snapshot-label');
  await labelInput.setValue(label);

  // Tap the trigger element
  const trigger = await driver.$('~memory-snapshot-trigger');
  await trigger.click();

  // Brief pause to let the native module write to disk
  await driver.pause(1000);
}

/**
 * Read accumulated memory snapshots from the device filesystem.
 */
export async function readSnapshots(): Promise<MemorySnapshot[]> {
  const isAndroid = (driver as any).isAndroid;
  const tmpPath = path.join(os.tmpdir(), 'memory-snapshots.json');

  if (isAndroid) {
    execSync(`adb pull /data/data/com.pocketpalai/files/memory-snapshots.json "${tmpPath}"`, {
      timeout: 10000,
    });
  } else {
    // iOS simulator: get app data container, read file directly
    const container = execSync(
      'xcrun simctl get_app_container booted ai.pocketpal data',
      {encoding: 'utf8', timeout: 5000}
    ).trim();
    const srcPath = path.join(container, 'Documents', 'memory-snapshots.json');
    fs.copyFileSync(srcPath, tmpPath);
  }

  const data = fs.readFileSync(tmpPath, 'utf8');
  return JSON.parse(data);
}

/**
 * Clear snapshots file on device (call at start of profiling session).
 * Uses host-side file deletion for reliability.
 */
export async function clearSnapshots(): Promise<void> {
  const isAndroid = (driver as any).isAndroid;

  try {
    if (isAndroid) {
      execSync('adb shell run-as com.pocketpalai rm files/memory-snapshots.json', {
        timeout: 5000,
      });
    } else {
      const container = execSync(
        'xcrun simctl get_app_container booted ai.pocketpal data',
        {encoding: 'utf8', timeout: 5000}
      ).trim();
      const filePath = path.join(container, 'Documents', 'memory-snapshots.json');
      if (fs.existsSync(filePath)) {
        fs.unlinkSync(filePath);
      }
    }
  } catch {
    // File may not exist yet, that's fine
  }
}
```

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Hidden zero-sized element not interactable by Appium | Med | Med | Fallback: use `position: absolute, left: -9999` instead of `width: 0, height: 0`. Both approaches keep element invisible but off-screen positioning ensures interactable dimensions. Test during implementation. |
| `xcrun simctl get_app_container` fails on CI or non-standard simulator setups | Low | Med | The command is standard Xcode tooling; document Xcode version requirement; E2E already depends on simulator infrastructure |
| `adb pull` fails due to app data being in device-protected storage | Low | Med | Use `run-as com.pocketpalai cat files/memory-snapshots.json` as fallback; or use Context.getExternalFilesDir() instead of filesDir on Android |
| `Debug.getPss()` may return 0 on some devices/emulators | Low | Low | Log warning but don't fail; PSS=0 is valid data point (documents limitation) |
| E2E spec takes too long (model download + 5 messages) | Med | Low | Use QUICK_TEST_MODEL (135M, fast download); configurable via TEST_MODELS env var |
| iOS `task_info` requires no special entitlements for own process | Low | Low | This is a standard API for querying own process memory; verified safe |

| TextInput setValue() inside zero-sized container may not work on Android | Low | Med | Test during implementation; if fails, use off-screen positioning approach |
