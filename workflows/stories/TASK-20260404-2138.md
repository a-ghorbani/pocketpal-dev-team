### Background
PocketPal maintains its own thinking model detection logic with hardcoded architecture lists and token pattern matching. This misses models like Gemma 4 that use different thinking formats. Meanwhile, llama.cpp already has comprehensive thinking detection covering 25+ model families, exposed via llama.rn's `getFormattedChat()` API with `thinking_start_tag`/`thinking_end_tag` fields.

### Current State
- `src/utils/thinkingCapabilityDetection.ts` — Hardcoded `KNOWN_THINKING_CAPABLE_ARCHITECTURES = ['qwen3', 'smollm3']`, manual `THINKING_TOKENS` list, brand-specific `templateSupportsThinking()` patterns, 4-level detection cascade
- `src/store/ModelStore.ts:2389-2411` — `updateModelThinkingCapabilities()` calls `supportsThinking(storeModel, ctx)` from the detection utility, only runs when `storeModel.supportsThinking === undefined`
- `src/store/ModelStore.ts:1571` — Called during `initContext()` after model load
- `src/store/defaultModels.ts:184,229,364` — Three models have explicit `supportsThinking: false` overrides (Qwen2.5 models and SmolLM2)
- `__mocks__/external/llama.rn.ts` — Mock does not include `getFormattedChat` method

### Target State
- `supportsThinking()` calls `ctx.getFormattedChat()` with `{jinja: true, enable_thinking: true}` and checks for non-empty `thinking_start_tag` in the result
- All hardcoded architecture lists, token lists, and brand-specific template patterns are removed
- `templateSupportsThinking()` is removed (no longer needed)
- `updateModelThinkingCapabilities()` in ModelStore passes context through unchanged
- Explicit `supportsThinking: false` overrides in `defaultModels.ts` continue to work (the `=== undefined` guard in ModelStore preserves them)
- llama.rn mock updated with `getFormattedChat` method

**Code Guidance**:
```typescript
import {LlamaContext, JinjaFormattedChatResult} from 'llama.rn';

export interface ThinkingDetectionResult {
  supported: boolean;
  thinkingStartTag?: string;
  thinkingEndTag?: string;
}

/**
 * Detects thinking capability by calling getFormattedChat with enable_thinking.
 * Delegates to llama.cpp's comprehensive detection covering 25+ model families.
 */
export async function detectThinkingCapability(
  ctx: LlamaContext,
): Promise<ThinkingDetectionResult> {
  try {
    const result = await ctx.getFormattedChat(
      [{role: 'user', content: 'test'}],
      null,
      {jinja: true, enable_thinking: true},
    );

    // JinjaFormattedChatResult has thinking_start_tag when model supports thinking
    const jinjaResult = result as JinjaFormattedChatResult;
    if (jinjaResult.thinking_start_tag) {
      return {
        supported: true,
        thinkingStartTag: jinjaResult.thinking_start_tag,
        thinkingEndTag: jinjaResult.thinking_end_tag,
      };
    }

    return {supported: false};
  } catch (error) {
    console.warn('Thinking capability detection failed:', error);
    return {supported: false};
  }
}
```

private async updateModelThinkingCapabilities(
  ctx: LlamaContext,
  model: Model,
) {
  try {
    const storeModel = this.models.find(m => m.id === model.id);
    if (!storeModel) {
      return;
    }

    // Only check if supportsThinking is not already explicitly set
    if (storeModel.supportsThinking === undefined) {
      const result = await detectThinkingCapability(ctx);

      runInAction(() => {
        storeModel.supportsThinking = result.supported;
        if (result.thinkingStartTag) {
          storeModel.thinkingStartTag = result.thinkingStartTag;
        }
        if (result.thinkingEndTag) {
          storeModel.thinkingEndTag = result.thinkingEndTag;
        }
      });
    }
  } catch (error) {
    console.error('Error updating model thinking capabilities:', error);
  }
}

describe('detectThinkingCapability', () => {
