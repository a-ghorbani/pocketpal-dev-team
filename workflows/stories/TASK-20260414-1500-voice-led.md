## Context

### Background
After PR #690 added Kitten + Kokoro engines and the four-section setup sheet, the user rejected the layout: *"the model sheet design is shit... I said beautiful UI. this is terrible."* The sheet is **engine-led** — four stacked sections (Kitten / Kokoro / Supertonic / System), each with its own install/download/voice-list block. Problems:

1. **First-open = four download walls.** A new user sees three "Install XX voices · Downloads ~N MB" CTAs before any voice is usable. The only immediately-working section (System) is at the bottom.
2. **Every subsequent open shows three irrelevant sections.** Once a user picks Kokoro, the Kitten + Supertonic + System sections are still there, occupying ~75% of the sheet.
3. **Engines are an implementation detail.** Users think *"which voice do I want?"*, not *"which engine should I install?"*
4. **No way to compare voices across engines** — voices grouped by engine, but a user picking by character (warm / bright / etc.) has no affordance.

### Current State
- `src/components/TTSSetupSheet/TTSSetupSheet.tsx` — mounts four sections in fixed order inside a `Sheet.ScrollView` at `snapPoints={['75%']}`.
- `src/components/TTSSetupSheet/KittenSection.tsx`, `KokoroSection.tsx`, `SupertonicSection.tsx`, `SystemSection.tsx` — each one renders its own section header, install/download/retry card (state machine: `not_installed | downloading | ready | error`) and voice row list. Supertonic section additionally renders a steps selector. Kitten/Kokoro/Supertonic sections are structurally near-identical.
- `src/services/tts/engines/{kitten,kokoro,supertonic,system}/voices.ts` — static `Voice[]` arrays (System is fetched dynamically). `Voice` type in `src/services/tts/types.ts` currently has `{id, name, engine, language?, gender?}` — no character/timbre field.
- `src/store/TTSStore.ts` — source of truth for: `currentVoice`, `autoSpeakEnabled`, `supertonicSteps`, and per-engine `{download,State,Progress,Error}` + `downloadXxx()` / `retryXxxDownload()` / `deleteXxx()`. **This story does not modify the store.**
- `TTS_PREVIEW_SAMPLE` and `getEngine(id).play(sample, voice)` already provide the preview path used by all sections.
- Sheet nested-navigation precedent: `src/components/PalsSheets/PalSheet.tsx:65,424` keeps a secondary sheet (`PalGenerationSettingsSheet`) as a separate `<Sheet>` opened by local `useState` — i.e., the pattern in this codebase is "second sheet on top", not "navigator inside one sheet".

### Target State
A voice-led sheet modelled on Apple Settings → Accessibility → Spoken Content → Voices.

Primary view (the sheet opens here every time):
1. **Hero row**: current voice big, with engine chip (e.g., "Kokoro · High quality"), optional character tag ("Warm"), and an inline ▶ preview button. Tapping the hero row opens Browse.
2. **Browse voices** → row: opens a secondary in-sheet view listing all voices from all engines, grouped by character (Warm / Clear / Deep / Bright). Each row: voice name · small engine chip · ▶ preview · ✓ if current. Voices whose engine is not installed render **dimmed** with no preview; tapping a dimmed voice opens a small confirm affordance with *"Install {Engine} to use this voice"* → Install button that kicks off the download in place (stays on Browse).
3. **Auto-speak responses** (switch).
4. **Quality (Supertonic)** row — visible only when `currentVoice?.engine === 'supertonic'`; reuses the existing steps selector control.
5. **Manage engines** → row: opens a secondary in-sheet view containing today's per-engine install / download / progress / delete controls, as de-emphasized `EngineRow`s (one per engine).

No four-up download wall on first open; engine detail is one tap away for users who care, invisible to users who don't.

## Requirements

### Functional
1. [MUST] Primary view shows hero row + Browse row + Auto-speak toggle + Manage engines row. Supertonic quality row appears only when `ttsStore.currentVoice?.engine === 'supertonic'`.
2. [MUST] Hero row preview button plays `TTS_PREVIEW_SAMPLE` via the current voice's engine (same path every other preview already uses).
3. [MUST] Browse view renders every voice from every engine in a single list grouped by `character` with section headers ordered Warm → Clear → Deep → Bright. Within a group, voices sort female-first then by display name.
4. [MUST] A voice whose engine `isInstalled()` is `false` (i.e., `ttsStore.<engine>DownloadState !== 'ready'` for neural engines; System is always ready) renders dimmed, is not selectable, and has no preview button.
5. [MUST] Tapping a dimmed voice expands an inline affordance showing *"Install {Engine} to use {Voice}"* with a single **Install** button. Install triggers `ttsStore.download{Engine}()`; the affordance switches to a progress fill driven by `download{Engine}Progress` / `download{Engine}State` and resolves to `ready` or `error` (with Retry). User stays in Browse; no navigation happens.
6. [MUST] Tapping a ready voice calls `ttsStore.setCurrentVoice(voice)` and closes the sheet — matches existing section behaviour.
7. [MUST] Manage engines view lists Kitten, Kokoro, Supertonic, System as stacked `EngineRow`s. Each row owns the install / downloading / ready+delete / error+retry state the current KittenSection/KokoroSection/SupertonicSection already implement. System is always `ready` and shows no action.
8. [MUST] Browse view must never render a download CTA card for an engine at the top — engines are not visible as sections in Browse.
9. [MUST] Add a per-voice `character: 'warm' | 'clear' | 'deep' | 'bright'` field to `Voice` (optional), with catalog default assignments for every Kitten / Kokoro / Supertonic / System voice (see Step 1). System voices that can't be classified default to `'clear'`.
10. [SHOULD] Back navigation inside the sheet (Browse → Primary, Manage → Primary) uses a left-chevron header button. Hardware back on Android should also pop from secondary to primary (not close the sheet) when a secondary view is active.
11. [SHOULD] Platform-adaptive chrome (iOS bottom-sheet / Android-style behaviour) is preserved — we do NOT introduce a new sheet wrapper; we reuse `<Sheet>`.

### Non-Functional
- Performance: no additional work on sheet open beyond what four sections already do — this is a UI refactor with less rendering on first paint (single list vs four sections).
- Compatibility: must match existing testIDs where feasible so downstream E2E smoke tests don't break. Where the testID no longer makes sense (e.g., `tts-kitten-section`), it moves into the Manage view.
- Security: none.

### Migration Considerations
- [x] Does this change affect stored user data/settings? **No.** `currentVoice`, `autoSpeakEnabled`, `supertonicSteps` are untouched. The persisted `currentVoice` still resolves by `{id, engine}` and renders correctly — only the picker UI that selects it changes.
- [x] Backwards compatibility: Voices restored from AsyncStorage lacking a `character` field still work — `character` is optional, and the Browse view looks it up from the static catalog by `{engine, id}`, not from the persisted `Voice` object.
- Migration strategy: **none needed**.

### Platform Verification
- N/A — no native changes. `NATIVE_CHANGES: NO`.

## Design decisions (resolved research questions)

**Q1 — Character metadata.** No field exists today (`grep character src/services/tts/**/voices.ts` → empty). Adding an optional `character` to `Voice` is a pure-data, non-breaking change. Persisted `currentVoice` in AsyncStorage lacks the field, so `HeroRow` must resolve character by catalog lookup (`{engine, id}`) rather than from the persisted object.

**Q2 — Sheet navigation pattern.** `@gorhom/bottom-sheet` does not provide an in-sheet navigator. The codebase precedent (`PalSheet.tsx` → `PalGenerationSettingsSheet`) uses a *second* `<Sheet>` opened from local state. We deliberately diverge here: we use **one `<Sheet>` host** and swap its body via `useState<'primary'|'browse'|'manage'>`. Rationale: (a) primary and secondary share one snap point and one close affordance; (b) re-opening the sheet always returns to primary, matching iOS Settings behaviour; (c) Android back handling is simpler with one host.

**Q3 — Dimmed voice interaction.** Chosen: **inline expansion with install-in-place** (option c from the prompt). Rejected (a) "navigate to Manage engines with the engine highlighted" because it takes the user away from the voice they just expressed interest in and re-introduces engine-centric thinking. Rejected (b) "confirm bottom-action" because two taps to get to an action we can offer in one is worse. Inline keeps the user's browse context, the progress fill is already a familiar visual, and once `ready` the row auto-promotes to selectable without re-tap.

**Q4 — Collapse sections into EngineRow?** Yes. Kitten/Kokoro/Supertonic sections are structurally identical (header, description, install-card state machine, voice rows). The only differences are: constants (engine id, l10n keys, store methods) and the Supertonic steps selector. Extracting `EngineRow` + `SupertonicStepsRow` is a clear win. System is slightly different (always ready, no download) but trivially expressible with one branch inside `EngineRow`.

**Q5 — Demolition list.** See Affected Files. `KittenSection`, `KokoroSection`, `SupertonicSection`, `SystemSection` are deleted; their behaviour is preserved in `EngineRow` (detail UI) + `VoicePickerView` (voice selection) + `SupertonicStepsRow` (steps). The `SupertonicSection.test.tsx` becomes redundant (its two concerns — state machine + steps selector — are covered by the two new test files).

## Coding Standards

### Testing Infrastructure
- Use `render` from `jest/test-utils.tsx` (provides BottomSheet + SafeArea).
- `runInAction(() => { ttsStore.xxx = ... })` for state changes.
- Don't mock `ttsStore` inline — it's globally mocked; mutate observables directly.
- Mock engine `play` via the `jest.mock('../../../services/tts', ...)` pattern already used in `SupertonicSection.test.tsx`.

### Patterns to Follow
- Functional components + `observer()` for any component reading MobX.
- Keep styles in `styles.ts`; don't inline. Existing `styles.ts` has the install-card styles — reuse.
- No `as ViewStyle` casts. No inline comments inside style objects.

### Commit Format
```
feat(tts): voice-led setup sheet with Browse and Manage views
```
Keep commits small: Step 1 (catalog), Step 2+3 (EngineRow/SupertonicStepsRow), Step 4+5 (Hero/AutoSpeak/VoicePicker), Step 6+7 (Manage + switcher), Step 8 (l10n), Step 9 (tests).

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Deleting four section components breaks downstream imports | Medium | Medium | `grep -rn 'KittenSection\|KokoroSection\|SupertonicSection\|SystemSection' src e2e` before delete; update `index.ts`. |
| Removing section testIDs breaks E2E smoke spec | Medium | Medium | `grep -rn 'tts-.*-section' e2e/` to enumerate, retain/move the IDs that E2E asserts on. |
| Character assignments feel arbitrary to users | Low | Low | Catalog defaults only; easy follow-up to curate without schema change. |
| Install-in-place UX looks cramped when progress bar runs inside Browse | Medium | Low | Reuse the same `installCardProgressFill` treatment the existing sections use — proven visual. |
| `getSystemVoices()` async call in VoicePickerView causes first-frame flash | Low | Low | Load once on mount with a loading placeholder for the System group only. |
| Stacked-branch base (PR #690) changes underneath | Medium | Low | Rebase on final merge; the UI layer has a narrow surface against `ttsStore`. |
| Hardware-back interception conflicts with `@gorhom/bottom-sheet` internal gesture | Medium | Medium | Use `BackHandler` subscription guarded by `isSetupSheetOpen && view !== 'primary'`; unit-test the handler path. |
