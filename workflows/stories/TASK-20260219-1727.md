### Background

Users want PocketPal to connect to external OpenAI-compatible servers (LM Studio, Ollama, OpenAI, Groq, etc.) in addition to running models locally on-device. This is the most requested feature category (GitHub #377, 3 thumbs-up; relates to broader ecosystem interest in #259 with 13 thumbs-up). The `completionTypes.ts` file already has a comment: "We should move towards OpenAI Compatible API Params" indicating this was anticipated.

### Current State

The chat completion flow is tightly coupled to `LlamaContext` from llama.rn:

1. **`useChatSession.ts`** (line 267): Calls `context.completion(cleanCompletionParams, callback)` where `context` is a `LlamaContext` from `modelStore.context`
2. **`ModelStore.ts`** (line 101): Holds `context: LlamaContext | undefined` - the only completion engine
3. **`ModelStore.ts`** (line 1460): `initContext()` calls `initLlama()` to create a `LlamaContext`
4. **`types.ts`** (line 327-331): `ModelOrigin` enum has `PRESET`, `LOCAL`, `HF` - no `REMOTE`
5. **`completionTypes.ts`**: `CompletionParams` extends llama.rn's `CompletionParams` - already OpenAI-compatible message format
6. **Model selection UI**: `HeaderRight.tsx` (line 52) uses `modelStore.availableModels` which filters `isDownloaded` models only

The streaming callback in `useChatSession.ts` (line 269) receives `TokenData` with `{token, content, reasoning_content}`. The final result is `NativeCompletionResult` with `{text, reasoning_content, content, timings, tokens_predicted, ...}`.

### Target State

1. A `CompletionEngine` interface formalizes the completion contract
2. `LocalCompletionEngine` wraps `LlamaContext` conforming to the interface
3. `OpenAICompletionEngine` implements the interface using fetch + SSE parsing
4. `ServerStore` (MobX, persisted) manages server configurations
5. Remote models from configured servers appear in the unified model list
6. `useChatSession` uses the engine interface instead of direct context calls
7. Server configuration UI lives in Settings screen
8. Stop button works for remote completions via `AbortController`
9. Existing local model functionality is completely unaffected

### Local-Only Features (NOT modified in v1)

These files use `modelStore.context` directly and will NOT work with remote models. They are explicitly out of scope for v1:

- **`src/hooks/useStructuredOutput.ts`** -- Structured output (JSON schema enforcement) requires local LlamaContext grammar support. For v1, if a remote model is active when structured output is attempted, a guard should show a message like "Structured output is only available with local models". This can be a simple `if (!modelStore.context)` check at the call site.
- **`src/screens/VideoPalScreen.tsx`** -- VideoPal uses `modelStore.context` for multimodal inference. For v1, if a remote model is active, show a message like "VideoPal requires a local model". This can be handled with the existing `modelStore.context` check.

Both should be addressed in a follow-up task when remote model capabilities expand.

### Known Limitations (v1)

- **Thinking/reasoning models**: `enable_thinking` and `reasoning_format` are llama.rn-specific params. The OpenAI thinking API uses a different mechanism. Remote thinking models will produce no reasoning output in v1. This is a known limitation to address in v2.
- **ChatGenerationSettingsSheet**: Shows 15+ llama.rn-specific settings (mirostat, grammar, penalty_*, n_probs, etc.) that have no effect on remote models. For v1, these remain visible. In v2, filter to show only universal params (temperature, top_p, max_tokens) when a remote model is active.

- [ ] Create `sseParser.ts` - Manual SSE parser with cross-chunk buffering:
  ```typescript
  // Parses a single SSE line: "data: {json}" -> object, "data: [DONE]" -> 'done', other -> null
  export function parseSSELine(line: string): object | null | 'done' {
    if (!line.startsWith('data: ')) return null;
    const data = line.slice(6).trim();
    if (data === '[DONE]') return 'done';
    try {
      return JSON.parse(data);
    } catch {
      return null;
    }
  }

  // Stateful SSE parser that handles incomplete lines split across chunks.
  // Usage: create once per stream, call feed() for each chunk.
  export class SSEParser {
    private buffer = '';

    /**
     * Feed a chunk of SSE data. Yields parsed events.
     * Buffers incomplete lines across calls (handles chunks split mid-line).
     */
    *feed(chunk: string): Generator<object | 'done'> {
      this.buffer += chunk;
      const lines = this.buffer.split('\n');
      // Last element may be incomplete (no trailing newline) — keep it in buffer
      this.buffer = lines.pop() || '';
      for (const line of lines) {
        const trimmed = line.trim();
        if (!trimmed) continue; // Skip empty lines between events
        const result = parseSSELine(trimmed);
        if (result !== null) yield result;
      }
    }

    /** Flush any remaining data in the buffer (call at end of stream). */
    *flush(): Generator<object | 'done'> {
      if (this.buffer.trim()) {
        const result = parseSSELine(this.buffer.trim());
        if (result !== null) yield result;
      }
      this.buffer = '';
    }
  }
  ```
  The key design: `lines.pop()` keeps the last (potentially incomplete) line in the buffer. On the next `feed()` call, the next chunk is appended, completing the line. This correctly handles cases where a chunk boundary falls in the middle of a `data: {...}\n` line.
- [ ] Create `openai.ts` - OpenAI-compatible API client:
  - `fetchModels(serverUrl: string, apiKey?: string): Promise<RemoteModelInfo[]>` - calls `GET /v1/models`

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| `useChatSession` refactoring breaks existing local chat | Medium | High | LocalCompletionEngine is a thin wrapper that delegates directly to LlamaContext - behavior is identical. Test both paths. |
| ReadableStream not available on all React Native platforms | Low | High | React Native 0.82 includes `fetch` with streaming support. Validation spike in Step 2 verifies this before building full engine. No XHR fallback -- find clean approach if needed. Check `TextDecoder` availability. |
| SSE parser edge cases (chunked data splitting mid-event) | Medium | Medium | `SSEParser` class uses stateful buffer: `lines.pop()` retains incomplete last line, next `feed()` appends to it. `flush()` at stream end processes remaining data. Test with various chunk sizes including mid-line splits. |
| ModelStore `availableModels` computed change breaks UI components | Medium | Medium | Remote models are appended to the existing filtered list. Existing filter logic (`isDownloaded`) is preserved for local models. |
| API key security - accidental exposure in logs | Low | High | Store in Keychain only. Never log API keys. Pass by reference (serverId) not by value. |
| Large number of remote models overwhelming the UI | Low | Low | Models screen already handles scrollable lists. Could add a limit or grouping by server in future. |
| OpenAI API spec deviations between providers | Medium | Medium | Stick to the core subset (chat completions, models list). All major providers (LM Studio, Ollama, Groq, OpenAI) support this subset. |
| `Model` interface bloat from optional remote fields | Low | Low | Only 3 optional fields added (`serverId`, `serverName`, `remoteModelId`). `createRemoteModel()` factory fills required fields with defaults. Consider a discriminated union in future refactor if more divergence appears. |
| `context` guard in `handleSendPress` blocks remote models | High | High | **Fixed in plan**: Guard on `modelStore.engine` instead of `modelStore.context`. Pass `contextId: string` to `prepareCompletion`. |
| `registerCompletionPromise` blocks model switching for remote | Medium | Medium | **Fixed in plan**: Only call `registerCompletionPromise` for local engines (when `modelStore.context` exists). Remote cleanup handled by `AbortController`. |
| `useStructuredOutput` / `VideoPalScreen` crash with remote model | Medium | Medium | **Documented as local-only for v1**. Both files continue to use `modelStore.context` directly. Guard messages added when remote model is active. |
| `ApiCompletionParams` carries llama.rn-specific fields to OpenAI engine | Low | Low | **Accepted tech debt for v1**. OpenAI engine picks only the fields it needs. Common `CompletionEngineParams` type planned for v2. |
