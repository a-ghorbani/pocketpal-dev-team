### File 10: `e2e/pages/SettingsPage.ts` — new page object

**What**: Create a new page object for the Settings screen to encapsulate navigation and interaction patterns.

**Pattern reference**: Follow `e2e/pages/ModelsPage.ts` structure (extends `BasePage`, declares `browser`/`driver` globals, has `waitForReady()`, action methods).

```typescript
/**
 * Settings Page Object
 * Handles interactions with the Settings screen
 *
 * Uses shared Selectors utility for consistent cross-platform selectors
 */

import {BasePage} from './BasePage';
import {Selectors, byText} from '../helpers/selectors';
import {Gestures} from '../helpers/gestures';

declare const browser: WebdriverIO.Browser;

export class SettingsPage extends BasePage {
  /**
   * Wait for settings screen to be ready.
   * Uses the "Model Initialization Settings" card title as the ready indicator
   * since the SettingsScreen has no top-level testID.
   * NOTE: This only works while the app is in English. After a language switch,
   * use waitForLanguageSelectorButton() instead.
   */
  async waitForReady(timeout = 10000): Promise<void> {
    await this.waitForElement(byText('Model Initialization Settings'), timeout);
  }

  /**
   * Scroll down to the language selector button.
   * The language selector is in the "App Settings" card, which is the 4th card
   * on the Settings screen. Needs multiple swipes to reach.
   */
  async scrollToLanguageSelector(): Promise<boolean> {
    return Gestures.scrollToElement(
      Selectors.settings.languageSelectorButton,
      5,
    );
  }

  /**
   * Tap the language selector button to open the language menu.
   */
  async openLanguageMenu(): Promise<void> {
    await this.tap(Selectors.settings.languageSelectorButton);
    // Brief pause for menu animation
    await browser.pause(500);
  }

  /**
   * Select a language from the open language menu.
   * @param lang - Language code (e.g., 'en', 'id', 'ja', 'zh')
   */
  async selectLanguage(lang: string): Promise<void> {
    await this.tap(Selectors.settings.languageOption(lang));
    // Wait for re-render after language change
    await browser.pause(1000);
  }

  /**
   * Wait for the language selector button to be visible (language-agnostic).
   * Useful after a language switch when text-based selectors would fail.
   */
  async waitForLanguageSelectorButton(timeout = 10000): Promise<void> {
    await this.waitForElement(
      Selectors.settings.languageSelectorButton,
      timeout,
    );
  }
}
```

### File 12: `e2e/specs/language.spec.ts` — new E2E spec

**What**: Create a new E2E test spec that verifies language switching works across all supported languages.

**Pattern reference**: Follow `e2e/specs/quick-smoke.spec.ts` structure (imports, `beforeEach` with page init and `waitForReady`, `afterEach` with failure screenshot, single `it` block).

#### Test flow

1. App starts on Chat screen (English by default)
2. Open drawer, navigate to Settings
3. Scroll to language selector
4. For each language in `['id', 'ja', 'zh', 'en']` (cycle through all, ending on `en` to leave clean state):
   a. Tap language selector button
   b. Tap the language option menu item
   c. Language change triggers re-render — screen scrolls to top automatically
   d. Assert the navigation header title changed (use `byText` with expected translated value)
   e. Take screenshot `language-${lang}.png`
   f. Scroll back down to language selector for next iteration

#### L10n values for assertions

The navigation header title comes from `screenTitles.settings` (`App.tsx:128`):

| Language | `screenTitles.settings` | `settings.modelInitializationSettings` |
|----------|------------------------|----------------------------------------|
| `en`     | `Settings`             | `Model Initialization Settings`        |
| `id`     | `Pengaturan`           | `Pengaturan Inisialisasi Model`        |
| `ja`     | `設定`                  | `モデル初期化設定`                       |
| `zh`     | `設置`                  | `模型初始化设置`                         |

The test asserts on the **screen header title** (`screenTitles.settings`) because:
- It is always visible at the top after a language switch (no scrolling needed)
- It is rendered by React Navigation as a native text element
- Each language has a unique value (no collisions)

The test also asserts on the **first card title** (`settings.modelInitializationSettings`) as a secondary check because:
- It is also visible at the top after the re-render scroll
- It validates that l10n context propagation works inside the screen content (not just the nav header)

#### Implementation

```typescript
/**
 * Language Switching Test: Verifies all supported languages
 *
 * Cycles through each language and asserts the UI updates.
 * Does NOT require a model to be loaded.
 *
 * Usage:
 *   yarn test:ios:local --spec specs/language.spec.ts
 *   yarn test:android:local --spec specs/language.spec.ts
 */

import * as fs from 'fs';
import * as path from 'path';
import {ChatPage} from '../pages/ChatPage';
import {DrawerPage} from '../pages/DrawerPage';
import {SettingsPage} from '../pages/SettingsPage';
import {byText} from '../helpers/selectors';
import {SCREENSHOT_DIR} from '../wdio.shared.conf';

declare const driver: WebdriverIO.Browser;
declare const browser: WebdriverIO.Browser;

/**
 * Expected translated values for assertion.
 * Keys: screenTitles.settings (navigation header)
 * Values: settings.modelInitializationSettings (first card title)
 */
const LANGUAGE_ASSERTIONS: Record<
  string,
  {screenTitle: string; firstCardTitle: string}
> = {
  en: {
    screenTitle: 'Settings',
    firstCardTitle: 'Model Initialization Settings',
  },
  id: {
    screenTitle: 'Pengaturan',
    firstCardTitle: 'Pengaturan Inisialisasi Model',
  },
  ja: {
    screenTitle: '設定',
    firstCardTitle: 'モデル初期化設定',
  },
  zh: {
    screenTitle: '設置',
    firstCardTitle: '模型初始化设置',
  },
};

// Order: start with non-English, end with English to restore default state
const LANGUAGE_ORDER = ['id', 'ja', 'zh', 'en'];

describe('Language Switching', () => {
  let chatPage: ChatPage;
  let drawerPage: DrawerPage;
  let settingsPage: SettingsPage;

  beforeEach(async () => {
    chatPage = new ChatPage();
    drawerPage = new DrawerPage();
    settingsPage = new SettingsPage();

    await chatPage.waitForReady(30000);
  });

  afterEach(async function (this: Mocha.Context) {
    if (this.currentTest?.state === 'failed') {
      const timestamp = new Date().toISOString().replace(/[:.]/g, '-');
      const testName = this.currentTest.title.replace(/\s+/g, '-');
      try {
        if (!fs.existsSync(SCREENSHOT_DIR)) {
          fs.mkdirSync(SCREENSHOT_DIR, {recursive: true});
        }
        await driver.saveScreenshot(
          path.join(SCREENSHOT_DIR, `failure-${testName}-${timestamp}.png`),
        );
      } catch (e) {
        console.error('Failed to capture screenshot:', (e as Error).message);
      }
    }
  });

  it('should switch between all supported languages', async () => {
    // Navigate: Chat -> Drawer -> Settings
    await chatPage.openDrawer();
    await drawerPage.waitForOpen();
    await drawerPage.navigateToSettings();
    await settingsPage.waitForReady();

    // Ensure screenshot directory exists
    if (!fs.existsSync(SCREENSHOT_DIR)) {
      fs.mkdirSync(SCREENSHOT_DIR, {recursive: true});
    }

    // Cycle through each language
    for (const lang of LANGUAGE_ORDER) {
      console.log(`\n--- Switching to: ${lang} ---`);
      const expected = LANGUAGE_ASSERTIONS[lang];

      // Scroll to the language selector
      const found = await settingsPage.scrollToLanguageSelector();
      if (!found) {
        throw new Error(
          `Could not find language selector button after scrolling`,
        );
      }

      // Open language menu and select the language
      await settingsPage.openLanguageMenu();
      await settingsPage.selectLanguage(lang);

      // After language change, screen re-renders and scrolls to top.
      // Assert the navigation header title changed.
      const titleElement = browser.$(byText(expected.screenTitle));
      await titleElement.waitForDisplayed({timeout: 5000});
      console.log(`  Screen title: "${expected.screenTitle}" - OK`);

      // Assert the first card title changed (visible at top after re-render).
      const cardTitleElement = browser.$(byText(expected.firstCardTitle));
      await cardTitleElement.waitForDisplayed({timeout: 5000});
      console.log(`  First card title: "${expected.firstCardTitle}" - OK`);

      // Take screenshot
      await driver.saveScreenshot(
        path.join(SCREENSHOT_DIR, `language-${lang}.png`),
      );
      console.log(`  Screenshot saved: language-${lang}.png`);
    }

    console.log('\n=== Language switching test complete ===');
  });
});
```

#### Key design decisions

1. **No separate `it` blocks per language**: A single `it` block cycles through all languages because each iteration depends on the previous one (the app stays on the Settings screen). Separate tests would require re-navigation each time, and the drawer label text changes after the first language switch, breaking `byText('Settings')` selectors.

2. **Language order ends with English**: The test ends on `en` to leave the app in the default state for any subsequent tests.

3. **`byText` for assertions, `byTestId` for actions**: We use `byTestId` to find and tap the language selector button and menu items (stable identifiers). We use `byText` for assertions to verify the actual displayed text changed.

4. **`scrollToElement` for language selector**: The language selector is far down the Settings page (4th card, "App Settings"). The `Gestures.scrollToElement` helper handles this with up to 5 swipes.

5. **`waitForReady` uses English text**: The initial `waitForReady()` looks for "Model Initialization Settings" text. This is fine because the app starts in English. After the first language switch, we use `byText(expected.screenTitle)` which is language-aware.

6. **`browser.pause(1000)` after language select**: The language change triggers a full re-render of the screen (MobX observable `uiStore.language` changes, `L10nContext.Provider` value updates). A 1-second pause gives React time to re-render.
