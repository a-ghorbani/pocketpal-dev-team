## Task Summary

**What**: Add a `detect-changes` job to `.github/workflows/ci.yml` that skips `build-android` and `build-ios` when all changed files are in `src/locales/`.

**Why**: Native builds are expensive (Android ~10min on ubuntu, iOS ~15min on macOS). Translation-only PRs (from Weblate or manual edits) only touch JSON files that cannot affect native builds. Skipping them saves CI minutes and speeds up translation workflow.

**Where**: `.github/workflows/ci.yml`

## Change Details

### File: `.github/workflows/ci.yml`

**1. Add `detect-changes` job (insert before `build-and-test`, lines 14-15)**

Add a new job between the `jobs:` key and the existing `build-and-test` job:

```yaml
  # Detect if changes are translation-only (src/locales/ files)
  detect-changes:
    runs-on: ubuntu-latest
    outputs:
      translation_only: ${{ steps.check.outputs.translation_only }}
    steps:
      - name: Check out code
        uses: actions/checkout@v3
        with:
          fetch-depth: 0

      - name: Check if translation-only
        id: check
        run: |
          if [ "${{ github.event_name }}" = "pull_request" ]; then
            CHANGED=$(git diff --name-only origin/${{ github.base_ref }}...HEAD)
          else
            CHANGED=$(git diff --name-only HEAD~1)
          fi

          echo "Changed files:"
          echo "$CHANGED"

          # Check if ALL changed files are under src/locales/
          TRANSLATION_ONLY="true"
          while IFS= read -r file; do
            if [ -z "$file" ]; then
              continue
            fi
            case "$file" in
              src/locales/*) ;;
              *) TRANSLATION_ONLY="false"; break ;;
            esac
          done <<< "$CHANGED"

          echo "translation_only=$TRANSLATION_ONLY" >> "$GITHUB_OUTPUT"
          echo "Translation only: $TRANSLATION_ONLY"
```

## Notes

- The `case` statement approach avoids needing `grep` with regex and handles filenames with special characters cleanly.
- `fetch-depth: 0` is required for `git diff origin/main...HEAD` to work in the PR context. Without it, the shallow clone won't have the base branch ref.
- For `push` events on `main`, `HEAD~1` is used since the push has already landed. This handles squash-merge of translation PRs.
- If there are zero changed files (edge case), `TRANSLATION_ONLY` stays `"true"`, which is harmless -- skipping native builds when nothing changed is correct.
- The `l10n-upload.yml` workflow is independent and already uses `paths:` trigger filtering, so no changes are needed there.
- The `e2e-tests.yml` workflow was not mentioned in the task scope. It could benefit from similar skipping but is out of scope for this task.
