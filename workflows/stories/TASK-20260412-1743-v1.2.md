## Context

### Background
After v1.0 (foundation) and v1.1 (UI + System end-to-end), the Supertonic section of the setup sheet is visible but disabled. This sub-story wires the Supertonic engine for real: downloads the neural model, stores it at the correct platform path with backup exclusion, enables the voice rows, and makes post-install Preview buttons synthesize live.

### Current State (after v1.0 + v1.1 merged)
- `SupertonicEngine` is a stub; `play()` throws. `isInstalled()` returns `false`.
- `SupertonicSection` renders 10 voice rows in a disabled placeholder state; Preview buttons are non-functional.
- No model download anywhere.
- No backup-exclusion code in the codebase (grep confirmed zero prior uses of `NSURLIsExcludedFromBackupKey`).
- RNFS available as `@dr.pogodin/react-native-fs` (`DownloadManager.ts:277` pattern).
- Android backup rules files exist: `android/app/src/main/res/xml/backup_rules_12_plus.xml` (contains both `cloud-backup` and `device-transfer` blocks) and `android/app/src/main/res/xml/backup_rules_legacy.xml`.

### Target State
- Supertonic model downloads on demand from a URL traced from the `@mhpdev/react-native-speech` fork example app at pinned SHA `3ae0094b094d7c3d4e17378e53199813384e88f9`.
- iOS storage: `${RNFS.LibraryDirectoryPath}/Application Support/tts/supertonic/` with `NSURLIsExcludedFromBackupKey = true` on the `tts/` directory.
- Android storage: `${RNFS.DocumentDirectoryPath}/tts/supertonic/` (maps to `getFilesDir()/tts/supertonic/`) with backup exclusion in both `backup_rules_12_plus.xml` (in both `cloud-backup` and `device-transfer` blocks) and `backup_rules_legacy.xml`.
- Setup sheet Supertonic section: install CTA card with color-fill progress while downloading; app remains usable during download. Once installed, voice rows become selectable; Preview button synthesizes `TTS_PREVIEW_SAMPLE` with that voice on-device.
- TTSStore `play()` no longer swallows Supertonic errors — real error surface (e.g., an in-sheet error state).
- **Bundled preview audio clips remain DEFERRED** — pre-install previews are still non-functional in v1.2.

## Implementation Notes (filled by implementer)

### Pinned SHA
`3ae0094b094d7c3d4e17378e53199813384e88f9` (installed at `node_modules/@mhpdev/react-native-speech`, verified).

### Traced from fork's `example/src/utils/SupertonicModelManager.ts`

Supertonic is **not a single model file** — it's a 4-ONNX pipeline + a unicode indexer. Five files are downloaded and one `voices-manifest.json` is synthesized locally post-download. Voice style embeddings are downloaded on-demand by the engine from a `baseUrl` recorded in the manifest (no pre-download needed for v1.2's voice list).

- **Base URL**: `https://huggingface.co/Supertone/supertonic/resolve/main`
- **Files** (v1 / English-only; v2 multilingual variant deferred):
  - `onnx/duration_predictor.onnx`
  - `onnx/text_encoder.onnx`
  - `onnx/vector_estimator.onnx`
  - `onnx/vocoder.onnx`
  - `onnx/unicode_indexer.json`
- **Voices base URL** (recorded in the local manifest): `https://huggingface.co/Supertone/supertonic/resolve/main/voice_styles`
- **Voice IDs** (matching the v1.0 catalog in `engines/supertonic/voices.ts`): `F1..F5, M1..M5`
- **Estimated total size**: ~265 MB (fork's constant; story originally said ~86 MB — updated).
- **No checksum** provided by the fork example; we rely on HuggingFace's TLS + `statusCode === 200` per-file gate.

### Fork API surface used
- `Speech.initialize({ engine: TTSEngine.SUPERTONIC, durationPredictorPath, textEncoderPath, vectorEstimatorPath, vocoderPath, unicodeIndexerPath, voicesPath, silentMode, ducking, maxChunkSize })` — initializes the engine; lazy (on first play).
- `Speech.speak(text, voiceId, {speed, inferenceSteps})` — synth + play.
- `Speech.stop()`, `Speech.onFinish(cb)`, `Speech.release()` — lifecycle.
- `RNFS.downloadFile({fromUrl, toFile, progress: res => res.bytesWritten / res.contentLength})` — per-file progress; overall progress is a sum across 5 files.

### Backup-exclusion approach: RNFS-native
`@dr.pogodin/react-native-fs` exposes `NSURLIsExcludedFromBackupKey` directly in `MkdirOptionsT` (`node_modules/@dr.pogodin/react-native-fs/src/NativeReactNativeFs.ts:109`). We pass `{NSURLIsExcludedFromBackupKey: true}` to `RNFS.mkdir` — **no Swift bridge needed**. This matches the fork example's own implementation. New-pattern-but-library-native — no codebase-local abstraction required. No new iOS native files.

### Storage paths
- **iOS**: `${RNFS.LibraryDirectoryPath}/Application Support/tts/supertonic/<file>` with `NSURLIsExcludedFromBackupKey=true` applied via `RNFS.mkdir`.
- **Android**: `${RNFS.DocumentDirectoryPath}/tts/supertonic/<file>` (which maps to `getFilesDir()/tts/supertonic/`), excluded via `backup_rules_12_plus.xml` (both `<cloud-backup>` and `<device-transfer>` blocks) and `backup_rules_legacy.xml`.

### Scope adjustments
- `getModelPath()` returns the *directory* (not a single file) since Supertonic is a 5-file bundle. `isInstalled()` verifies every required file exists.
- No `src/services/tts/backupExclusion.ts` wrapper is created — `RNFS.mkdir({NSURLIsExcludedFromBackupKey: true})` is used inline where the directory is created.
- No Swift bridge. The iOS `BackupExclusion.swift`/`.m` files listed in the story's "Affected Files" are NOT created.
