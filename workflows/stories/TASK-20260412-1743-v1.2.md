## Context

### Background
After v1.0 (foundation) and v1.1 (UI + System end-to-end), the Supertonic section of the setup sheet is visible but disabled. This sub-story wires the Supertonic engine for real: downloads the neural model, stores it at the correct platform path with backup exclusion, enables the voice rows, and makes post-install Preview buttons synthesize live.

### Current State (after v1.0 + v1.1 merged + v1.2 R1 implementation)
- Initial v1.2 implementation wired to **Supertonic v1** (`Supertone/supertonic` HuggingFace repo; English-only).
- Initial v1.2 added `scripts/postinstall.sh` as a workaround for an espeak-ng submodule build gap in the fork.
- Unit tests (426) green.
- Native Release builds blocked by the espeak-ng `config.h` autoconf gap (fork-internal).

### Target State (R2)
- Supertonic model downloads on demand from **Supertonic v2** (multilingual: EN/KO/ES/PT/FR) at `https://huggingface.co/Supertone/supertonic-2/resolve/main`. Same 5-file manifest, same ~265 MB total, same 10 voices (F1–F5, M1–M5).
- Fork re-pinned to the latest `add/neural-tts` SHA after espeak-ng is stripped upstream. `scripts/postinstall.sh` deleted.
- Language is a parameter on synthesis calls. v1.2 hardcodes `'en'` as the default; no UI selector. Language picker is follow-up `v1b-tts-language`.
- iOS storage: `${RNFS.LibraryDirectoryPath}/Application Support/tts/supertonic/` with `NSURLIsExcludedFromBackupKey = true` on the `tts/` directory.
- Android storage: `${RNFS.DocumentDirectoryPath}/tts/supertonic/` excluded via `backup_rules_12_plus.xml` (both `<cloud-backup>` and `<device-transfer>` blocks) and `backup_rules_legacy.xml`.
- Setup sheet Supertonic section: install CTA → color-fill progress → enabled voice rows + live preview post-install; error + Retry surface real engine failures.
- **Bundled preview audio clips remain DEFERRED** — pre-install previews non-functional in v1.2.

## Implementation Notes

### Pinned SHA (R1 → R2)
- **R1 (superseded)**: `3ae0094b094d7c3d4e17378e53199813384e88f9` — required postinstall workaround for espeak-ng autoconf gap.
- **R2 (current)**: _TBD at implementation time — latest commit on `add/neural-tts` after espeak-ng is stripped upstream._ **Implementer must record the exact SHA here before committing.**

### Supertonic v2 migration
- Base URL: `https://huggingface.co/Supertonic/supertonic-2/resolve/main` (was `.../Supertone/supertonic/resolve/main` in R1).
- Same 5-file manifest, same filenames (`onnx/duration_predictor.onnx`, `onnx/text_encoder.onnx`, `onnx/vector_estimator.onnx`, `onnx/vocoder.onnx`, `onnx/unicode_indexer.json`).
- Same 10 voices (F1–F5, M1–M5) — shared across all 5 languages.
- Total size ~265 MB (OnnxSlim-optimized; same as v1).
- Fork auto-detects v1 vs v2 by inspecting `unicode_indexer.json` — **no PocketPal-side version detection**.
- Verified in fork's `example/src/utils/SupertonicModelManager.ts:54-68` at the pinned SHA.

### Language strategy (v1.2)
- Hardcoded `'en'` default on all synthesis calls. No UI selector.
- Rationale: Supertonic v2 covers 5 languages; PocketPal UI ships 10+. Auto-binding synthesis language to UI locale would mislead users whose locale isn't in {EN, KO, ES, PT, FR}. System TTS remains the realistic fallback for other locales.
- Follow-up `v1b-tts-language` (see below) adds a proper selector with UX review.

### `SupertonicLanguage` shim widening
- Fork's internal type still declares `'en'` only. PocketPal's shim at `src/types/shims/mhpdev-react-native-speech.d.ts` exports `SupertonicLanguage = 'en' | 'ko' | 'es' | 'pt' | 'fr'` so engine code is type-safe today and the v1b PR can consume it without a shim edit.

### Espeak-ng workaround removal
- `scripts/postinstall.sh` (R1 artifact, commit `d850574` + `e5c1ffd`) was a two-part workaround: (1) `bob build --target module` for missing `lib/` in the fork's GitHub install, and (2) espeak-ng submodule clone + autoconf. Upstream strip removes the espeak-ng submodule entirely.
- R2 deletes `scripts/postinstall.sh` in full if the fork now publishes `lib/` in its tarball. If `lib/` is still absent post-strip, retain the minimal `bob build --target module` step only (espeak-ng lines removed) and document why in this section.
- No espeak-ng references should remain in CI workflows, docs, or scripts added during v1.2.

### Fork API surface (R2)
- `Speech.initialize({ engine: TTSEngine.SUPERTONIC, durationPredictorPath, textEncoderPath, vectorEstimatorPath, vocoderPath, unicodeIndexerPath, voicesPath, silentMode, ducking, maxChunkSize })` — lazy on first play.
- `Speech.speak(text, voiceId, { speed, inferenceSteps, language })` — language parameter added in v2. PocketPal passes `language ?? 'en'`.
- `Speech.stop()`, `Speech.onFinish(cb)`, `Speech.release()` — unchanged.
- `RNFS.downloadFile({fromUrl, toFile, progress})` — per-file progress; overall progress sums across 5 files.

### Backup-exclusion approach (unchanged from R1)
`@dr.pogodin/react-native-fs` exposes `NSURLIsExcludedFromBackupKey` in `MkdirOptionsT` (`node_modules/@dr.pogodin/react-native-fs/src/NativeReactNativeFs.ts:109`). Passed inline to `RNFS.mkdir` — no Swift bridge. No `src/services/tts/backupExclusion.ts`, no `ios/PocketPalAI/BackupExclusion.swift`/`.m`.

### Storage paths (unchanged from R1)
- **iOS**: `${RNFS.LibraryDirectoryPath}/Application Support/tts/supertonic/<file>` with `NSURLIsExcludedFromBackupKey=true`.
- **Android**: `${RNFS.DocumentDirectoryPath}/tts/supertonic/<file>` (= `getFilesDir()/tts/supertonic/`), excluded via both backup-rules XMLs.

### Scope adjustments (unchanged from R1)
- `getModelPath()` returns the directory (5-file bundle).
- `isInstalled()` verifies all 5 files.
