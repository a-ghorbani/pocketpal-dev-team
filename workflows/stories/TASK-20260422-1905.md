## Context

### Background

On Samsung S26 Ultra (Adreno A8X), PocketPal's static OpenCL quant whitelist in `src/utils/deviceSelection.ts:222` (`['q4_0', 'q6_k']`) is wrong in **both** directions:

- Q5_K_M runs dramatically better on GPU than CPU (~300 vs 45 pp/s, 24 vs 18 tg/s) — should be allowed.
- Q2_K regresses TG by ~50% on GPU (9 vs 18 tg/s) — should be blocked or warned.

A static whitelist cannot capture this. We need **measured data** to drive the eventual fix. This task builds the measurement infrastructure ONLY — no product behaviour changes. Acting on the data (updating the whitelist, UX changes) is an explicit follow-up.

### Current State

- `src/screens/BenchmarkScreen/BenchmarkScreen.tsx` has a full UI benchmark flow that calls `modelStore.context.bench(pp, tg, pl, nr)` (llama.rn) and stores results in `benchmarkStore.results` via `addResult()`. Result includes `ppAvg`, `tgAvg`, `wallTimeMs`, `peakMemoryUsage`, model meta, and `initSettings` snapshot.
- `src/store/BenchmarkStore.ts` is MobX-persisted to AsyncStorage. `latestResult` getter returns `results[0]` (newest first via `unshift`).
- `llama.rn` exposes `bench(pp, tg, pl, nr): Promise<BenchResult>` with `speedPp`, `speedTg`, and config fields (`nGpuLayers`, `flashAttn`, `nThreads`, etc.) — see `node_modules/llama.rn/src/index.ts:304-323,904-933`.

### Target State

1. **New spec** `e2e/specs/benchmark-matrix.spec.ts` iterates `{models} × {quants} × {backends}` (32 or 48 runs depending on conditional 3rd model slot), driving the existing UI Benchmark screen for each cell. For each run:
   - Sets device tier via SettingsPage helper (CPU tier: tap `device-option-cpu`; GPU tier: tap `device-option-gpu`). `n_gpu_layers` stays at its default 99 in both tiers, which is moot for CPU and correct for GPU.
   - Loads the model variant (GGUF for the specific quant).
   - Captures logcat during model load + benchmark to derive **effective backend**.
   - Reads benchmark result via `BenchmarkResultTrigger` (new component, mirrors `MemorySnapshotTrigger`).
   - Writes one canonical JSON row per run.
2. **Canonical report** `e2e/debug-output/benchmarks/benchmark-<device_slug>-<commit_sha>.json` with full metadata (device, SoC, commit, llama_rn_version, timestamp) and per-run fields (model_id, quant, requested_backend, effective_backend, pp_avg, tg_avg, wall_ms, peak_memory_mb, log_signals, status). 4. **New product-code component** `BenchmarkResultTrigger` — small (~70 LOC), mirrors `MemorySnapshotTrigger` exactly, exposes `benchmarkStore.latestResult` to E2E via `accessibilityLabel`. Same ship pattern (hidden at `GestureHandlerRootView` root).

## Requirements

### Functional

1. [MUST] Spec runs end-to-end on Android (S26 Ultra + Adreno A8X is the target device; spec must be device-agnostic on Android).
2. [MUST] Matrix is 2 or 3 models × 8 quants × 2 backends. The 3rd model slot is CONDITIONAL on HuggingFace publisher availability — see Requirement #3. Default matrix size: **32 runs (2 models) or 48 runs (3 models)**.
3. [MUST] Model slots:
   - **Slot 1 (unconditional)**: Qwen3 1.7B — `bartowski/Qwen_Qwen3-1.7B-GGUF`. Verify all 8 quants present on bartowski OR lmstudio-community during Step 1.
   - **Slot 2 (unconditional)**: Gemma 3 1B — `bartowski/google_gemma-3-1b-it-GGUF`. If any rung missing on bartowski, try `bartowski/google_gemma-3n-E2B-it-GGUF`. Verify during Step 1.
   - **Slot 3 (CONDITIONAL)**: LFM2 1.2B — attempt `bartowski/LiquidAI_LFM2-1.2B-GGUF` or latest LFM2.5 small text-only. **Include ONLY if all 8 quants are present on a reputable publisher.** Otherwise, SHIP V1 WITH 2 MODELS and document LFM2 as follow-up in the fixture file.
   - Rationale for conditionality: the infrastructure is the value; architectural-diversity (non-transformer LFM2) is preserved if available, but the 2-model matrix is a legitimate v1 if not.
4. [MUST] Environment-variable filters: `BENCH_MODELS`, `BENCH_QUANTS`, `BENCH_BACKENDS` (comma-separated, case-insensitive).
5. [MUST] `MODELS_PRESEEDED=1` mode:
   - Skips HF downloads entirely.
   - Pre-flight check: the spec queries the app's list of known downloaded models via the `BenchmarkResultTrigger` protocol (`list::models` command — see Step 2) and compares presence against the matrix-expected set BEFORE the iteration loop.
   - If any expected file is missing in preseeded mode, the spec **fails fast** with a clear error message pointing at the specific missing file AND the `adb push` command that would fix it. (Mixing preseed + download within one matrix run defeats the point; fail loudly rather than silently download.)
   - On-device preseed path (Android debug APK): `/data/data/com.pocketpalai/files/models/hf/<author>/<repo>/<filename>.gguf` — matches `ModelStore.getModelFullPath` at `src/store/ModelStore.ts:870` where `DocumentDirectoryPath = /data/data/com.pocketpalai/files` (RNFS convention).
   - Preseed requires a **debug APK**, because Android release APK is non-debuggable (verified: no `android:debuggable` override in `android/app/src/main/AndroidManifest.xml` and no `debuggable = true` in release build type in `android/app/build.gradle`). `adb shell run-as com.pocketpalai` and `adb push` into `/data/data/...` require the app to be debuggable. Documented as a precondition in the README "How to run" section.
   - Preseed workflow (for human operator, documented in README):
     ```bash
     # 1. Build debug APK (in worktree, NOT in submodule):
     cd android && ./gradlew assembleDebug && cd ..
     adb install android/app/build/outputs/apk/debug/app-debug.apk

     # 2. Push each preseeded GGUF (run once per variant):
     adb shell run-as com.pocketpalai mkdir -p files/models/hf/bartowski/Qwen_Qwen3-1.7B-GGUF
     adb push Qwen_Qwen3-1.7B-Q4_0.gguf /data/local/tmp/
     adb shell run-as com.pocketpalai sh -c 'cat /data/local/tmp/Qwen_Qwen3-1.7B-Q4_0.gguf > files/models/hf/bartowski/Qwen_Qwen3-1.7B-GGUF/Qwen_Qwen3-1.7B-Q4_0.gguf'
     # (repeat for each quant per model)

     # 3. Optionally: use the provided helper script e2e/scripts/preseed-models.sh
     #    (out of scope for v1; documented as a manual step.)
     ```
6. [MUST] Even without `MODELS_PRESEEDED`, download wall-time is **never** counted in per-run timings — download is a separate pre-phase.
7. [MUST] Tier definition (resolved v2.0): tier = SegmentedButton selection only.
   - **CPU tier**: tap `device-option-cpu`. Result: `{devices: ['CPU'], n_gpu_layers: 99}`. Verified `handleDeviceSelect` at `src/screens/SettingsScreen/SettingsScreen.tsx:236-249` only mutates `devices`; `n_gpu_layers` stays at its default 99 (`src/utils/contextInitParamsVersions.ts:246`).
   - **GPU tier**: tap `device-option-gpu`. Result: `{devices: [<adreno_name>], n_gpu_layers: 99}`.
   - `n_gpu_layers=99` is **moot** for CPU tier: when `devices=['CPU']`, llama.rn assigns every layer to the CPU device regardless of `n_gpu_layers` (verified via `node_modules/llama.rn/cpp/llama-model.cpp:3014-3026` and `jsi/RNLlamaJSI.cpp:333-375` — the JSI `buildDeviceOverrides` builds `params.devices = [cpu_dev]` and `load_tensors` then routes every `il` to `cpu_dev`).
   - **No slider driving. No programmatic `n_gpu_layers` mutation.** The spec asserts the resulting store state via the `BenchmarkResultTrigger`'s `read::initSettings` command before each bench run as a correctness check.
8. [MUST] For each run, spec captures logcat (Android) during model-load + benchmark and derives an **effective backend** label (`cpu` | `opencl` | `cpu+opencl-partial` | `unknown`) from OpenCL log signals. Report includes BOTH `requested_backend` and `effective_backend`. Structured `log_signals` payload per run — see Step 5.
9. [MUST] Spec writes one JSON report per run session: `e2e/debug-output/benchmarks/benchmark-<device_slug>-<commit_sha>.json`. The report is written incrementally after each run so that a mid-matrix crash preserves completed rows.
10. [MUST] `benchmark-compare.ts` diffs two reports, flags rows where |delta| > 15% on pp OR tg, exits 1 on any regression, 0 otherwise.
11. [MUST] Fixture schema change is backward-compatible: existing specs using `model.downloadFile` continue to work without modification.
12. [MUST] Default `bench()` call: `pp=512, tg=128, pl=1, nr=1`. `nr=1` keeps per-cell bench short so the full matrix wall clock is tractable; per-cell variance is captured by re-running the matrix rather than per-cell averaging. Override via `BENCH_NR` env var (e.g., `BENCH_NR=3` for stability-focused runs). No second knob — `BENCH_PP`, `BENCH_TG`, `BENCH_PL` may be added in a follow-up if needed; not in v1.
13. [MUST] Spec is RUNNABLE but not wired into CI (CI integration is explicit out-of-scope).
14. [SHOULD] Default Gemma slot is `Gemma 3 1B` (bartowski `bartowski/google_gemma-3-1b-it-GGUF` has all 8 quants). If a quant is missing, swap is documented in fixture file, not silently dropped. Verification during Step 1.
15. [SHOULD] Hexagon NPU tier explicitly excluded from v1. Document in spec header as follow-up.

### Non-Functional

- Performance: Full matrix wall-time on S26 Ultra is bounded. Approximate budget per run: ~15-25 s for bench + ~20-40 s for load + ~5 s for device-tier switch = ~45 s/cell. 32 cells ≈ 24-30 min (pre-seeded, 2-model matrix); 48 cells ≈ 35-45 min (3-model matrix). Spec must not have hard per-run timeouts tighter than 5 min for the worst-case quant.
- Compatibility: Android-first. iOS is explicitly out-of-scope (Metal has different fallback semantics).
- Security: None. Logcat output is app log only, not system-wide.

- No backwards compat concerns for end users. No stored data affected.

export interface LogcatCapture {
  lines: string[];
  stop(): string[];
}

const BENCH_LOG_RE = /(lm_ggml_opencl|ggml_backend_|Adreno large buffer|offloaded \d+\/\d+ layers|load_tensors:|llama_model_load|ggml_cl|adreno_gen)/;

export function startCapture(udid?: string): LogcatCapture {
  const base = udid ? ['-s', udid] : [];
  try { execSync(['adb', ...base, 'logcat', '-G', '4M'].join(' '), {timeout: 5000}); } catch {}
  execSync(['adb', ...base, 'logcat', '-c'].join(' '), {timeout: 5000});
  const proc = spawn('adb', [...base, 'logcat', '-v', 'brief']);
  const lines: string[] = [];
  proc.stdout.on('data', (chunk: Buffer) => {
    for (const line of chunk.toString('utf8').split('\n')) {
      if (BENCH_LOG_RE.test(line)) lines.push(line);
    }
  });
  return {
    lines,
    stop() { proc.kill('SIGTERM'); return lines; },
  };
}
