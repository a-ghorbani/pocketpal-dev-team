### Background
llama.rn ships prebuilt `xcframework` (iOS) and `.so` files (Android) in its npm package. When pointing `package.json` to a git commit instead of an npm version, those prebuilts are not available so the library must be compiled from source. The build-from-source flags already exist in llama.rn:
- **iOS**: `RNLLAMA_BUILD_FROM_SOURCE=1` env var (read by `llama-rn.podspec` line 28)
- **Android**: `rnllamaBuildFromSource=true` gradle property (read by `build.gradle` line 20)

But CI does not set them, and there is no easy developer toggle to switch between npm and git ref.

### Current State
- `package.json` line 51: `"llama.rn": "0.12.0-rc.3"` (npm version, prebuilts available)
- `android/gradle.properties` line 42: `# rnllamaBuildFromSource=true` (commented out)
- `.github/workflows/ci.yml`: No detection of git refs, no source build flags, no C++ caching
- `scripts/postinstall.sh`: Already clones OpenCL headers (needed for source builds)
- `ios/Podfile`: Forces llama-rn to static library (line 62-71), no env var for `RNLLAMA_BUILD_FROM_SOURCE`

### Target State
- CI auto-detects git refs in `package.json` and sets build-from-source flags
- iOS CI: exports `RNLLAMA_BUILD_FROM_SOURCE=1` before `pod install` and `xcodebuild`
- Android CI: sets `rnllamaBuildFromSource=true` in `gradle.properties` when detected
- Android `.cxx` build artifacts cached (iOS DerivedData intentionally NOT cached — see Risks)
- Toggle script at `tools/use-llama-rn-source.sh` for developer convenience
- `package.json` updated to point to the crash-fix commit

**Change**:

- [ ] Output `llama_from_source=true/false` as a job output

**Code Guidance**:
```yaml
# Add to detect-changes job outputs
outputs:
  translation_only: ${{ steps.check.outputs.translation_only }}
  llama_from_source: ${{ steps.check-llama.outputs.llama_from_source }}

# New step in detect-changes job (after existing check step)
- name: Check if llama.rn needs source build
  id: check-llama
  run: |
    if grep '"llama.rn"' package.json | grep -q '#'; then
      echo "llama_from_source=true" >> "$GITHUB_OUTPUT"
      echo "llama.rn points to git ref - source build required"
    else
      echo "llama_from_source=false" >> "$GITHUB_OUTPUT"
      echo "llama.rn is npm version - using prebuilts"
    fi
```

**Why pure shell**: The `detect-changes` job runs on `ubuntu-latest` with no `setup-node` step. Pre-installed Node on runners is fragile and unnecessary here. `grep` is simpler and has zero dependencies.

**Pattern Reference**: See existing `detect-changes` job in `ci.yml` lines 15-51 for output pattern.

### Step 2: Set iOS source build flags in CI
**Files**: `.github/workflows/ci.yml`
**Status**: `PENDING`

**Change**:
- [ ] In `build-ios` job, add a conditional step that exports `RNLLAMA_BUILD_FROM_SOURCE=1` when `llama_from_source` is true
- [ ] The env var must be set for BOTH the `pod install` step AND the `xcodebuild` step
- [ ] Simplest approach: add a step that writes to `$GITHUB_ENV`
- [ ] No iOS DerivedData caching (intentionally omitted — see Risks section)

**Code Guidance**:
```yaml
build-ios:
  runs-on: macos-15
  needs: [build-and-test, detect-changes]
  if: needs.detect-changes.outputs.translation_only != 'true'
  steps:
    # ... existing steps ...

    - name: Set llama.rn source build flags
      if: needs.detect-changes.outputs.llama_from_source == 'true'
      run: echo "RNLLAMA_BUILD_FROM_SOURCE=1" >> "$GITHUB_ENV"

    # pod install step already exists - RNLLAMA_BUILD_FROM_SOURCE
    # is now in GITHUB_ENV so it's automatically available

    # xcodebuild step already exists - env var available
```

**Important**: The `RNLLAMA_BUILD_FROM_SOURCE` env var set via `$GITHUB_ENV` persists for all subsequent steps in the job. No changes needed to existing `pod install` or `xcodebuild` steps.

**Why no DerivedData caching**: Xcode DerivedData at `~/Library/Developer/Xcode/DerivedData` uses unpredictable hashed folder names, can be 5-10GB+, and GitHub Actions has a 10GB cache limit. Cache hits are unreliable and would crowd out more useful caches. A custom `-derivedDataPath` could work but adds xcodebuild flag complexity for marginal gain. The Android `.cxx` cache is far more targeted and effective.

**Pattern Reference**: See `ci.yml` lines 309-313 (pod install) and lines 320-333 (xcodebuild).

```yaml
build-android:
  runs-on: ubuntu-latest
  needs: [build-and-test, detect-changes]
  if: needs.detect-changes.outputs.translation_only != 'true'
  steps:
    # ... existing steps ...

    - name: Set llama.rn source build flags
      if: needs.detect-changes.outputs.llama_from_source == 'true'
      run: |
        sed -i 's/# rnllamaBuildFromSource=true/rnllamaBuildFromSource=true/' android/gradle.properties
        echo "Enabled rnllamaBuildFromSource in gradle.properties"
        grep rnllamaBuildFromSource android/gradle.properties

    # Cache .cxx for source builds
    - name: Cache Android NDK build
      if: needs.detect-changes.outputs.llama_from_source == 'true'
      uses: actions/cache@v4
      with:
        path: |
          node_modules/llama.rn/android/.cxx
        key: ${{ runner.os }}-android-cxx-${{ hashFiles('package.json') }}
        restore-keys: |
          ${{ runner.os }}-android-cxx-
```

**Note**: Use `actions/cache@v4` for new cache steps. Existing `actions/cache@v3` usages elsewhere in the file are left as-is (out of scope for this task).

**Important**: The `sed` command must match exactly the commented-out line in `gradle.properties` (line 42: `# rnllamaBuildFromSource=true`). Place this step BEFORE the `Build Android Release` step.

**Pattern Reference**: See `android/gradle.properties` line 42 and `ci.yml` lines 99-201 for build-android job.

### Step 4: Create toggle script
**Files**: `tools/use-llama-rn-source.sh`
**Status**: `PENDING`

**Change**:
- [ ] Create `tools/` directory (does not exist in pocketpal-ai repo yet)
- [ ] Create `tools/use-llama-rn-source.sh` with usage: `./tools/use-llama-rn-source.sh <commit-or-version-or-owner/repo#sha>`
- [ ] If argument looks like a semver (e.g., `0.12.0`), set npm version and comment out `rnllamaBuildFromSource`
- [ ] If argument contains `/` (e.g., `myfork/llama.rn#abc123`), treat as full GitHub owner/repo#sha ref
- [ ] If argument is a bare hex string (e.g., `0ee4fe6...`), prefix with `mybigday/llama.rn#`
- [ ] Script should print next steps (yarn install, pod install) but NOT auto-run them

**Code Guidance**:
```bash
#!/bin/bash
set -euo pipefail

usage() {
  echo "Usage: $0 <commit-sha|owner/repo#sha|npm-version>"
  echo ""
  echo "Examples:"
  echo "  $0 0ee4fe686aacb534cd2759ee09ca382a4cf41624  # git commit (mybigday/llama.rn)"
  echo "  $0 myfork/llama.rn#abc123def                   # fork ref (source build)"
  echo "  $0 0.12.0-rc.3                                  # npm version (prebuilt)"
  exit 1
}

[ $# -ne 1 ] && usage

VERSION_OR_REF="$1"
SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
PROJECT_ROOT="$(cd "$SCRIPT_DIR/.." && pwd)"
PACKAGE_JSON="$PROJECT_ROOT/package.json"
GRADLE_PROPS="$PROJECT_ROOT/android/gradle.properties"

# Detect: semver-like = npm, contains "/" = full GitHub ref, otherwise = bare commit hash
if echo "$VERSION_OR_REF" | grep -qE '^[0-9]+\.[0-9]+'; then
  # npm version (e.g., "0.12.0-rc.3")
  echo "Setting llama.rn to npm version: $VERSION_OR_REF"
  node -e "
    const fs = require('fs');
    const pkg = JSON.parse(fs.readFileSync('$PACKAGE_JSON', 'utf8'));
    pkg.dependencies['llama.rn'] = '$VERSION_OR_REF';
    fs.writeFileSync('$PACKAGE_JSON', JSON.stringify(pkg, null, 2) + '\n');
  "
  # Comment out rnllamaBuildFromSource
  sed -i'' -e 's/^rnllamaBuildFromSource=true/# rnllamaBuildFromSource=true/' "$GRADLE_PROPS"
  echo "Disabled rnllamaBuildFromSource in gradle.properties"
  echo ""
  echo "Next steps:"
  echo "  yarn install"
  echo "  cd ios && pod install"
elif echo "$VERSION_OR_REF" | grep -q '/'; then
  # Full GitHub ref (e.g., "myfork/llama.rn#abc123")
  echo "Setting llama.rn to GitHub ref: $VERSION_OR_REF"
  node -e "
    const fs = require('fs');
    const pkg = JSON.parse(fs.readFileSync('$PACKAGE_JSON', 'utf8'));
    pkg.dependencies['llama.rn'] = '$VERSION_OR_REF';
    fs.writeFileSync('$PACKAGE_JSON', JSON.stringify(pkg, null, 2) + '\n');
  "
  # Uncomment rnllamaBuildFromSource
  sed -i'' -e 's/^# rnllamaBuildFromSource=true/rnllamaBuildFromSource=true/' "$GRADLE_PROPS"
  echo "Enabled rnllamaBuildFromSource in gradle.properties"
  echo ""
  echo "Next steps:"
  echo "  yarn install"
  echo "  RNLLAMA_BUILD_FROM_SOURCE=1 pod install --project-directory=ios"
else
  # Bare commit hash — prefix with mybigday/llama.rn#
  echo "Setting llama.rn to git commit: mybigday/llama.rn#$VERSION_OR_REF"
  node -e "
    const fs = require('fs');
    const pkg = JSON.parse(fs.readFileSync('$PACKAGE_JSON', 'utf8'));
    pkg.dependencies['llama.rn'] = 'mybigday/llama.rn#$VERSION_OR_REF';
    fs.writeFileSync('$PACKAGE_JSON', JSON.stringify(pkg, null, 2) + '\n');
  "
  # Uncomment rnllamaBuildFromSource
  sed -i'' -e 's/^# rnllamaBuildFromSource=true/rnllamaBuildFromSource=true/' "$GRADLE_PROPS"
  echo "Enabled rnllamaBuildFromSource in gradle.properties"
  echo ""
  echo "Next steps:"
  echo "  yarn install"
  echo "  RNLLAMA_BUILD_FROM_SOURCE=1 pod install --project-directory=ios"
fi
```

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|

| Git ref resolution fails in CI (network) | Low | Medium | yarn install would fail early with clear error |
