## Context

### Background
PocketPal AI is a privacy-first on-device LLM chat app. Users want TTS so the assistant can speak its responses. We're integrating `react-native-speech` (System TTS via AVSpeechSynthesizer / Android TextToSpeech, plus an on-device neural engine **Supertonic**).

This is v1, with a deliberate UX posture: **Supertonic is the product we're shipping**. System TTS exists as an honest accessibility fallback, labeled as such. We are NOT shipping "easy TTS with optional neural upgrade" — that framing buries the value we built. Every user-facing surface is designed so that a new user's first interaction presents Supertonic as the obvious choice.

Two user-facing controls remain:
1. **REPLAY** — per-message inline play button on assistant messages
2. **MODE** — input-bar split chip: toggle auto-speak (left half) + open setup (right half)

**CHARACTER** (per-Pal voice) is deferred to follow-up story v1b.

### Current State
- No TTS infrastructure. No `react-native-speech` dep, no TTSStore, no voice UI anywhere.
- `src/store/index.ts` exports 9 stores.
- Assistant messages render via `src/components/TextMessage/TextMessage.tsx`; chat bubble rendering wires through `src/components/ChatView/ChatView.tsx:186,721,742`.
- Chat input: `src/components/ChatInput/ChatInput.tsx` (~632 lines).
- Settings: `src/screens/SettingsScreen/SettingsScreen.tsx` (~1174 lines) — same card/accordion pattern for sections.
- AppState listener pattern: `src/store/ModelStore.ts:664-745`.
- RAM check pattern: `src/utils/deviceCapabilities.ts:205` using `react-native-device-info@^14.1.1` (`DeviceInfo.getTotalMemory()`). `ModelStore.ts:538` and `UsageStats.tsx:48` also use it.
- Downloads: `src/services/downloads/DownloadManager.ts` uses `@dr.pogodin/react-native-fs@^2.36.0` (RNFS) with `DocumentDirectoryPath`. No prior use of `LibraryDirectoryPath` or `NSURLIsExcludedFromBackupKey` in this codebase — implementer will introduce.
- Completion-write hook: the final `updateMessage()` call in `src/hooks/useChatSession.ts` where `completionResult: { reasoning_content, content }` is written (same location modified in PR #578 for the thinking-block fix). This is where `onAssistantMessageComplete(messageId, text)` must fire.
- Locales: `src/locales/en.json` only — rest via Weblate.
- Android XML resources live in `android/app/src/main/res/xml/` (existing files: `backup_rules_12_plus.xml`, `backup_rules_legacy.xml`, `network_security_config.xml`).

### Target State
- `react-native-speech` installed, pinned to a commit SHA on branch `add/neural-tts` (temporary WIP fork).
- A **hard memory gate**: at app start `TTSStore.isTTSAvailable` is computed once from `DeviceInfo.getTotalMemory() >= 6 GiB`. If false, no TTS UI renders anywhere. There is no "TTS not available" row or toast — the feature simply doesn't exist for that device.
- When available but no voice is chosen yet, **every TTS entry point opens the same setup bottom sheet**. No implicit engine, no playback "for free." The user picks a voice before any audio plays.
- Setup sheet presents **Supertonic voices first** (featured with a CTA to download ~86 MB if not installed, and bundled 1-2s preview clips per voice so users can audition before deciding). System voices appear below, each labeled `"System voice · robotic, for accessibility"`.
- Input-bar control is a **split chip** with two tap targets separated by a vertical divider (each ≥44pt wide): left half = auto-speak toggle showing speaker state + current voice name label; right half = gear icon opening the setup sheet. Pre-setup state = gear-only chip. Voice name label truncates responsively (full → first 3 chars → icon-only).
- Per-message play button: tap-with-no-voice opens setup sheet; after voice is chosen, tap plays (simple icon swap speaker⇄stop; no morph, no progress bar, no long-press menu). Only rendered on assistant text messages with >1 word after streaming completes.
- Settings → Voice & Speech (also gated on `isTTSAvailable`): single "Voice" row. Tapping it opens the same setup sheet. Plus a Preview button that speaks the shared `TTS_PREVIEW_SAMPLE` with the currently chosen voice. No separate Engine row, no Manage Engines screen, no rate slider.
- Supertonic model download card lives inside the setup sheet near the Supertonic section header. Non-blocking, color-fill progress bar. Model stored at `Library/Application Support/tts/supertonic/` on iOS (with `NSURLIsExcludedFromBackupKey` on the directory) and `<filesDir>/tts/supertonic/` on Android (with backup-rules exclusion).
- Bundled preview audio: `assets/tts-previews/supertonic-<voiceId>.m4a`. Same 1-2s sample sentence across voices, ≈50 KB each. After Supertonic installs, preview switches from bundled clip to on-device synthesis of `TTS_PREVIEW_SAMPLE`.
- Lifecycle: switching chat session stops playback; app backgrounded stops playback (no background audio). iOS audio session category = `AVAudioSessionCategoryPlayback` (interactive media, ignores silent switch).
