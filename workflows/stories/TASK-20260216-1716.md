### Background
GitHub issue #551 reports that LLM-generated markdown tables are not rendered in PocketPal. The app uses `marked` (GFM enabled) to convert markdown to HTML, and `react-native-render-html` v6.3.4 to render the HTML. However, `react-native-render-html` v6 categorizes table elements (`table`, `thead`, `tbody`, `tr`, `td`, `th`) as "tabular" and does NOT render them by default -- they are silently dropped with a dev-mode warning.

The `@native-html/transient-render-engine` (the parsing engine under `react-native-render-html`) defines UA styles for the native tabular models as a reference for what table layout needs:
- `tr`: `{ flexDirection: 'row', flexWrap: 'nowrap' }`
- `td`/`th`: `{ flex: 1, padding: 2 }` (plus `fontWeight: 'bold'` for `th`)

**Important**: These UA styles belong to the native `fromNativeModel` definitions and are NOT inherited by `fromCustomModel`. Our custom element models start with a blank style slate. All necessary layout styles must be provided via `tagsStyles` in Step 2.

### Current State
- **`src/components/MarkdownView/MarkdownView.tsx`** -- The main markdown component. Uses `marked` to parse markdown to HTML, then `RenderHtml` to render. Currently has one custom renderer (`code`) for syntax-highlighted code blocks. No table handling at all.
- **`src/components/MarkdownView/styles.ts`** -- Defines `createTagsStyles()` returning styles for `body`, `code`, `pre`, `thinking`/`think`/`thought` tags. No table-related styles.
- **`marked`** already produces valid `<table>`, `<thead>`, `<tbody>`, `<tr>`, `<th>`, `<td>` HTML from GFM table syntax.
- **`react-native-render-html`** v6.3.4 drops these tags because they have content model `none` by default in the render layer.

### Target State
After this change:
- Markdown tables render as visible, styled Flexbox-based tables
- Table headers (`<th>`) are visually distinct: bold text + different background color
- Tables respect light/dark theme via the existing `useTheme()` hook
- Wide tables are horizontally scrollable via a wrapping `ScrollView`
- Only `table` tag has a custom renderer (for ScrollView wrapper); all other table tags use the library's built-in default renderers once promoted via `customHTMLElementModels`
- Element models and the single custom renderer live in `TableRenderers.tsx`; all tag styles live in `styles.ts`
- No new npm dependencies required

**Key insight from external review**: Once `customHTMLElementModels` promotes table tags from "tabular/dropped" to "block/mixed", the library's built-in default renderers handle everything — wrapping in Views, rendering children, applying tagsStyles. Custom renderers for `thead`, `tbody`, `tr`, `th`, `td` are no-ops (they just replicate what the default renderers already do). Only `table` needs a custom renderer for the ScrollView wrapper.

**Bonus**: The library automatically sets `testID: tnode.tagName` on default-rendered elements (`getNativePropsForTNode.ts:73`), giving us `testID="tr"`, `testID="td"` etc. for free in tests.

**Pattern Reference**: See `node_modules/react-native-render-html/src/__tests__/regression.276.cusom-renderer-wrapper.test.tsx:17-42` for the pattern of defining `customHTMLElementModels` + `renderers`.

**Code Guidance**:

```typescript
// src/components/MarkdownView/TableRenderers.tsx
import React from 'react';
import {View, ScrollView, StyleSheet} from 'react-native';
import {
  HTMLElementModel,
  HTMLContentModel,
  TNodeChildrenRenderer,
} from 'react-native-render-html';
import type {
  CustomBlockRenderer,
  CustomTagRendererRecord,
  HTMLElementModelRecord,
} from 'react-native-render-html';

// Element models: Tell react-native-render-html to treat table tags as renderable
// elements instead of silently dropping them (default "tabular" category = not rendered).
// Once promoted, the library's built-in default renderers handle Views, children,
// and tagsStyles automatically — no custom renderers needed for these 5 tags.
export const tableHTMLElementModels: HTMLElementModelRecord = {
  table: HTMLElementModel.fromCustomModel({
    tagName: 'table',
    contentModel: HTMLContentModel.block,
  }),
  thead: HTMLElementModel.fromCustomModel({
    tagName: 'thead',
    contentModel: HTMLContentModel.block,
  }),
  tbody: HTMLElementModel.fromCustomModel({
    tagName: 'tbody',
    contentModel: HTMLContentModel.block,
  }),
  tr: HTMLElementModel.fromCustomModel({
    tagName: 'tr',
    contentModel: HTMLContentModel.block,
  }),
  th: HTMLElementModel.fromCustomModel({
    tagName: 'th',
    contentModel: HTMLContentModel.mixed,
  }),
  td: HTMLElementModel.fromCustomModel({
    tagName: 'td',
    contentModel: HTMLContentModel.mixed,
  }),
};

// Only `table` needs a custom renderer — for the ScrollView wrapper.
// All other table tags use the library's built-in default renderers.
const TableRenderer: CustomBlockRenderer = ({tnode, style}) => {
  // Separate border/frame styles for the outer wrapper from inner layout styles.
  // Border must be on the outer View so it stays fixed while content scrolls.
  const {borderWidth, borderColor, borderRadius, overflow, marginVertical, ...innerStyle} =
    StyleSheet.flatten(style) || {};
  return (
    <View style={{borderWidth, borderColor, borderRadius, overflow, marginVertical}}>
      <ScrollView horizontal nestedScrollEnabled>
        <View style={[{minWidth: '100%'}, innerStyle]}>
          <TNodeChildrenRenderer tnode={tnode} />
        </View>
      </ScrollView>
    </View>
  );
};

export const tableRenderers: CustomTagRendererRecord = {
  table: TableRenderer,
};
```

**IMPORTANT implementation notes**:
- `HTMLContentModel.mixed` for `th`/`td` because they contain inline text content
- `HTMLContentModel.block` for `table`/`thead`/`tbody`/`tr` because they contain other block-level elements
- Only `table` gets a custom renderer. The other 5 tags rely on the library's built-in default block/mixed renderers which automatically render children and apply tagsStyles
- Border/frame styles must be on the outer wrapper `View`, NOT the inner content `View`, so the frame stays fixed while content scrolls horizontally

### Step 2: Add Table Tag Styles
**Files**: `src/components/MarkdownView/styles.ts`
**Status**: `DONE`

**Change**:
- [ ] Add table-related tag styles directly in `createTagsStyles()` (all styles live in `styles.ts`, consistent with existing pattern)
- [ ] Use a border strategy that minimizes double-thickness at edges

**Pattern Reference**: See `src/components/MarkdownView/styles.ts:5-58` for existing tag style pattern.

**Border strategy**: React Native has no `border-collapse`, so `table`'s outer `borderWidth: 1` combined with `tr`'s `borderBottomWidth: 1` produces 2px at the bottom edge, and `td`/`th`'s `borderRightWidth: 1` produces 2px at the right edge. At 1px on a high-DPI mobile screen this is subtle and acceptable. An alternative (borderTop/borderLeft on table + existing bottom/right on cells) would give exactly 1px everywhere but adds complexity for marginal visual gain.

**Code Guidance**:
```typescript
// In styles.ts, add to createTagsStyles return object:
export const createTagsStyles = (theme: Theme) => ({
  body: { /* existing */ },
  code: { /* existing */ },
  pre: { /* existing */ },
  thinking: { /* existing */ },
  think: { /* existing */ },
  thought: { /* existing */ },
  // Table styles — only `table` has an outer border frame;
  // inner structure uses bottom borders on rows and right borders on cells.
  table: {
    borderWidth: 1,
    borderColor: theme.colors.outline,
    borderRadius: 4,
    marginVertical: 8,
    overflow: 'hidden' as const,
  },
  thead: {
    backgroundColor: theme.colors.surfaceContainerHigh,
  },
  tr: {
    flexDirection: 'row' as const,
    borderBottomWidth: 1,
    borderBottomColor: theme.colors.outline,
  },
  th: {
    flex: 1,
    padding: 8,
    fontWeight: 'bold' as const,
    borderRightWidth: 1,
    borderRightColor: theme.colors.outline,
    backgroundColor: theme.colors.surfaceContainerHigh,
  },
  td: {
    flex: 1,
    padding: 8,
    borderRightWidth: 1,
    borderRightColor: theme.colors.outline,
  },
});
```

**Note on `flex: 1` for `th`/`td`**: These elements have `HTMLContentModel.mixed`, so the engine may produce either `TBlock` (View) or `TPhrasing`/`TText` (Text) tnodes. In practice, `<td>text</td>` produces `TBlock` wrapping inline content, so `flex: 1` participates in Flexbox correctly. This should be verified during manual testing — check that columns are equal width.

```typescript
const CodeRenderer = ({TDefaultRenderer, ...props}: any) => {
  const theme = useTheme();
  const styles = createStyles(theme);
  const isCodeBlock = props?.tnode?.parent?.tagName === 'pre';

  if (!isCodeBlock) {
    return <TDefaultRenderer {...props} />;
  }

  const language =
    props.tnode?.domNode?.attribs?.class?.replace('language-', '') || 'text';

  const rawHtml =
    props.tnode?.init?.domNode?.rawHTML ||
    props.tnode?.domNode?.rawHTML ||
    props.tnode?.domNode?.children?.[0]?.data ||
    '';

  const content = decodeHTMLEntities(rawHtml);

  return (
    <View>
      <CodeBlockHeader language={language} content={content} />
      <CodeHighlighter
        hljsStyle={atomOneDark}
        language={language}
        textStyle={styles.codeHighlighterText}
        scrollViewProps={{
          contentContainerStyle: styles.codeHighlighterScrollContent,
        }}>
        {content}
      </CodeHighlighter>
    </View>
  );
};
```
