## Context (For Recovery After Context Reset)

### Background
After downloading certain models (e.g., PrismML Bonsai-1.7B), `loadLlamaModelInfo` from llama.rn throws an uncaught C++ `std::runtime_error`. This crashes the app. On next startup, `loadMissingGGUFMetadata()` finds the model still has `ggufMetadata === undefined` and retries, causing the same crash -- infinite crash loop until user wipes app storage.

### Current State
- `src/store/ModelStore.ts:1179` - `fetchAndPersistGGUFMetadata()` calls `loadLlamaModelInfo()` (line 1189). The try-catch at line 1274 catches JS errors but the C++ `std::runtime_error` from llama.rn crashes the process before the catch block executes.
- `src/store/ModelStore.ts:1283` - `loadMissingGGUFMetadata()` filters models where `isDownloaded && !ggufMetadata` and retries `fetchAndPersistGGUFMetadata()` for each.
- `src/store/ModelStore.ts:550` - `loadMissingGGUFMetadata()` is called during store initialization (every app startup).
- `src/hooks/useMemoryCheck.ts:31-33` - `hasEnoughMemory()` also calls `fetchAndPersistGGUFMetadata()` if metadata is missing.
- The Model type (`src/utils/types.ts:398`) has `ggufMetadata?: GGUFMetadata` but no flag to indicate a previous fetch failure.

### Target State
1. llama.rn upgraded to 0.12.0-rc.5 which catches the C++ exception and returns a JS error instead of crashing.
2. When `fetchAndPersistGGUFMetadata()` fails, a `ggufMetadataFailed` flag is set on the model to prevent `loadMissingGGUFMetadata()` from retrying on every startup.
3. The flag is cleared when the model is re-downloaded (so a re-download can retry).
4. `loadMissingGGUFMetadata()` skips models with `ggufMetadataFailed === true`.

## Requirements

### Functional
1. [MUST] Upgrade llama.rn from 0.12.0-rc.3 to 0.12.0-rc.5
2. [MUST] Add `ggufMetadataFailed?: boolean` field to the Model type
3. [MUST] Set `ggufMetadataFailed = true` when `fetchAndPersistGGUFMetadata()` catches an error
4. [MUST] Skip models with `ggufMetadataFailed === true` in `loadMissingGGUFMetadata()`
5. [MUST] Clear `ggufMetadataFailed` when a model download completes (so re-download retries)
6. [SHOULD] Clear `ggufMetadataFailed` wherever `ggufMetadata` is cleared (migration resets at lines 2178, 2197)

### Non-Functional
- Performance: No impact -- flag check is a simple boolean comparison in the filter
- Compatibility: Existing users with `ggufMetadataFailed === undefined` will behave as before (falsy)

### Migration Considerations
- [x] Does this change affect stored user data/settings? Yes -- adds new field to persisted Model objects
- [x] Is backwards compatibility needed for existing users? Yes, but `undefined` is falsy so no migration needed
- Migration strategy: `none needed`
- Notes: `ggufMetadataFailed` defaults to `undefined` (falsy), so existing persisted models without this field will continue to be retried as before. Only models that fail after the update will get the flag.
