## Context (For Recovery After Context Reset)

### Background
GitHub issue #291 requests lifting the n_predict limit. In llama.cpp, `n_predict = -1` means "generate until EOS" (unlimited), `0` means no generation, and positive values set a hard token cap. The current app restricts n_predict to `[1, 4096]` with a default of `1024`, which is unnecessarily limiting — users should be able to set -1 for unlimited generation.

Additionally, `validateCompletionSettings` at line 174 of `modelSettings.ts` has a latent bug: it checks `!validateNumericField(...)` which tests truthiness of the returned **object** `{isValid, errorMessage}` — an object is always truthy, so the negation is always `false`, meaning validation errors are silently swallowed. The fix is to check `.isValid` on the returned object.

### Current State
- `src/utils/completionSettingsVersions.ts:29` — `n_predict` default is `1024`
- `src/utils/modelSettings.ts:35` — validation rule: `{min: 1, max: 4096}`
- `src/utils/modelSettings.ts:174` — `!validateNumericField(...)` checks object truthiness (always truthy), so validation always passes (bug)
- `src/utils/modelSettings.ts:16-19` — `ValidationRule` numeric type requires `min` and `max` as mandatory `number` fields
- `src/utils/modelSettings.ts:153-158` — `validateNumericField` checks `numValue >= rule.min && numValue <= rule.max` and formats error as "Value must be between {min} and {max}"
- `src/locales/en.json:413` — n_predict description: "Set how long the generated response should be (in tokens)"
- `CURRENT_COMPLETION_SETTINGS_VERSION = 3`
- Per-model defaults in `defaultModels.ts` use `n_predict: 500` — these must NOT change
- `src/utils/__tests__/modelSettings.test.ts:124-132` — existing test iterates all `COMPLETION_PARAMS_METADATA` and asserts `min <= max` for numeric rules; this will break when `max` becomes optional

### Target State
- `n_predict` default: `-1` (unlimited, generate until EOS)
- `n_predict` validation: `min: -1`, no upper cap (remove `max: 4096`)
- `ValidationRule` type: `min` and `max` become optional to support open-ended bounds
- `validateNumericField`: handle optional `min`/`max` (skip bound check when undefined)
- Error messages: contextual ("Value must be at least {min}", "Value must be at most {max}", "Value must be between {min} and {max}")
- `validateCompletionSettings`: fix bug — check `.isValid` instead of object truthiness
- Migration v4: conditionally set `n_predict` to `-1` only when value equals old default (`1024`), preserving intentional user choices
- l10n: update en.json description to explain -1 = unlimited, 0 = no generation

**Status**: `PENDING`

**Change**:
- [ ] Make `min` and `max` optional in the `ValidationRule` numeric type: `{type: 'numeric'; min?: number; max?: number; required?: boolean}`
- [ ] Update `validateNumericField` range check (line 153) to skip min/max when undefined:
  ```typescript

  const belowMax = rule.max === undefined || numValue <= rule.max;
  const isValid = aboveMin && belowMax;
  ```
- [ ] Update error message (line 156-158) to be contextual:
  - Both bounds: `Value must be between ${rule.min} and ${rule.max}`
  - Only min: `Value must be at least ${rule.min}`
  - Only max: `Value must be at most ${rule.max}`
- [ ] Update `validateCompletionSettings` error message (line 178) to use the same contextual logic (or reuse from `validateNumericField` result)

**Pattern Reference**: See existing `validateNumericField` at `src/utils/modelSettings.ts:122-160`

**Code Guidance**:
```typescript
// ValidationRule type change
export type ValidationRule =
  | {type: 'numeric'; min?: number; max?: number; required?: boolean}
  | {type: 'array'; required?: boolean}
  | {type: 'boolean'; required?: boolean};

// Range check in validateNumericField
const aboveMin = rule.min === undefined || numValue >= rule.min;
const belowMax = rule.max === undefined || numValue <= rule.max;
const isValid = aboveMin && belowMax;

// Contextual error message
let errorMessage: string | undefined;
if (!isValid) {
  if (rule.min !== undefined && rule.max !== undefined) {
    errorMessage = `Value must be between ${rule.min} and ${rule.max}`;
  } else if (rule.min !== undefined) {
    errorMessage = `Value must be at least ${rule.min}`;
  } else if (rule.max !== undefined) {
    errorMessage = `Value must be at most ${rule.max}`;
  }
}
return {isValid, errorMessage};
```
