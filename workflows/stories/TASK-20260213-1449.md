### Background

PocketPal has E2E tests using Appium + WebDriverIO that currently support:
- Local iOS simulator testing via `wdio.ios.local.conf.ts` (hardcoded to `iPhone 17 Pro` / `26.0`)
- Local Android emulator testing via `wdio.android.local.conf.ts` (hardcoded to `emulator-5554` / `16`)
- AWS Device Farm testing via `wdio.ios.conf.ts` / `wdio.android.conf.ts` (env-var-driven)

The goal is to create a **local multi-device test pipeline** that can run E2E tests sequentially across multiple simulators, emulators, and USB-connected real devices from a single command. This enables a dedicated test laptop to validate PRs across a fleet of devices.

### Current State

**WDIO local configs** (`e2e/wdio.ios.local.conf.ts`, `e2e/wdio.android.local.conf.ts`):
- Device name, platform version, and app path are hardcoded
- No env var overrides for device selection
- Appium port is hardcoded to default (4723, via WDIO service default)

**Existing scripts** (`e2e/scripts/`):
- `run-model-tests.ts` - Sequential model testing, JUnit XML merging, `execSync` pattern
- `run-crash-repro.ts` - CLI arg parsing with `--flag value` pattern
- `run-aws-device-farm.ts` - AWS integration, artifact download

**Shared config** (`e2e/wdio.shared.conf.ts`):
- Already uses env vars for `OUTPUT_DIR` and `SCREENSHOT_DIR`
- JUnit reporter configured with `outputDir`
- All shared reporter, mocha, and runner settings centralized

### Target State

1. **WDIO local configs** accept env vars with backward-compatible defaults
2. **Device inventory** (`devices.json`) describes available devices per machine
3. **Pipeline script** (`run-e2e-pipeline.ts`) iterates over devices sequentially, runs WDIO for each, aggregates reports
4. **Package.json scripts** provide convenient entry points

```typescript
function runDeviceTest(device: DeviceConfig, spec: string, appiumPort: number, reportDir: string): DeviceTestResult {
  const startTime = Date.now();
  const configFile = device.platform === 'ios' ? 'wdio.ios.local.conf.ts' : 'wdio.android.local.conf.ts';

  // Determine spec file(s)
  const specArg = spec === 'all' ? '' : `--spec specs/${spec}.spec.ts`;

  // Per-device JUnit output directory
  const deviceReportDir = path.join(reportDir, device.id);
  fs.mkdirSync(deviceReportDir, { recursive: true });

  console.log(`\n${'='.repeat(60)}`);
  console.log(`Device: ${device.name} (${device.id})`);
  console.log(`Platform: ${device.platform} | Type: ${device.type}`);
  console.log(`Appium port: ${appiumPort}`);
  console.log(`${'='.repeat(60)}\n`);

  try {
    execSync(
      `npx wdio ${configFile} ${specArg}`,
      {
        stdio: 'inherit',
        cwd: path.join(__dirname, '..'),
        env: {
          ...process.env,
          E2E_DEVICE_NAME: device.deviceName,
          E2E_PLATFORM_VERSION: device.platformVersion,
          ...(device.udid && { E2E_DEVICE_UDID: device.udid }),
          ...(device.appPath && { E2E_APP_PATH: device.appPath }),
          E2E_APPIUM_PORT: String(appiumPort),
          // Direct JUnit output to device-specific directory
          DEVICEFARM_LOG_DIR: deviceReportDir,
          DEVICEFARM_SCREENSHOT_PATH: path.join(deviceReportDir, 'screenshots'),
        },
      },
    );
    // ...
  } catch (error) {
    // ...
  }
}
```

### Resolved
- Sequential vs parallel execution -> Sequential (Phase 1 decision)
- Appium port management -> Base 4723 + device index offset
- devices.json committed vs gitignored -> gitignored (machine-specific), template committed
- `--source` checkout -> **NO** — pipeline does NOT do git checkouts. Separation of concerns: caller (skill/human) handles checkout, pipeline handles test execution. Avoids self-modification hazard where checkout could change the running script.
- `--dry-run` flag -> **YES** — add `--dry-run` that prints matched devices, build commands, and WDIO commands without executing. Standard practice for long-running pipelines.
