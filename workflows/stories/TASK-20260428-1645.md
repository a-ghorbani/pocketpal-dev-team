## Context

### Background

The repo is the PocketPal workflow control plane. The target app code lives in
`repos/pocketpal-ai` and remains read-only. Agent workflow definitions currently
live mainly in `AGENTS.md`, `CLAUDE.md`, `.claude/agents/`, `.claude/skills/`,
and shared source folders.

The previous story draft tried to normalize every agent, skill, rule, and tool
adapter at once. That is too broad. Phase 1 should only migrate the generic
external PR/code review workflow while keeping the current Claude delivery
pipeline working.

### Current State

- `AGENTS.md` is the intended cross-tool operating contract.
- `CLAUDE.md` imports `AGENTS.md` via `@AGENTS.md`.
- Claude Code automatically loads `CLAUDE.md` and its `@` imports for subagents,
  verified locally with a marker-reporter test.
- Claude project agents load from `.claude/agents/*.md`.
- Claude skills load from `.claude/skills/*/SKILL.md`.
- Codex reads `AGENTS.md` by default.
- Codex does not read `CODEX.md` by default, so `CODEX.md` is redundant.
- Codex runtime skills were locally validated in `~/codes/test-cc` under
  `.codex/skills/Bamboo/SKILL.md`, importing shared source from
  `skills/Bamboo/SKILL.md`, with codex-cli 0.125.0.
- Root `skills/` is shared source only; it is not a Codex runtime discovery path.
- `~/.codex/config.toml` `[[skills.config]]` can toggle already discovered
  skills but does not add discovery roots.
- The former `.claude/rules` standing rules now belong in `AGENTS.md`.
- The former visual capture rule is a workflow/procedure, not a standing rule.
- `.claude/agents/pocketpal-pr-reviewer.md` is the generic external PR/code
  review agent.
- `.claude/agents/pocketpal-reviewer.md` is the implementation pipeline quality
  gate after implementation/testing and before draft PR. It is a different role.
- OpenCode is not currently used for this migration target.
