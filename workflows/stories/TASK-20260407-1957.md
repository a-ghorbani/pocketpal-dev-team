## Context (For Recovery After Context Reset)

### Background
When a user taps "+" and picks a local GGUF file, `handleAddLocalModel` in `ModelsScreen.tsx` copies it to the app's internal storage then registers it in ModelStore. Three problems exist:

1. **No feedback during file copy**: `RNFS.copyFile()` can take seconds/minutes for large GGUF files (several GB). There is ZERO visual feedback — the user sees nothing happening and may think the app froze or the upload failed.

2. **Duplicate model entries on "Replace"**: When a file with the same name already exists and the user chooses "Replace", the old FILE is deleted (`RNFS.unlink`) but the old MODEL ENTRY in `modelStore.models` remains. Then `addLocalModel()` creates a NEW entry with a new UUID. Result: two model cards pointing to the same `fullPath`.

3. **Redundant `setTrigger` hack**: Line 250 uses `setTrigger(prev => !prev)` to force a re-render. This is unnecessary since `modelStore.models` is observable and the component is an `observer`. The same hack exists on line 109 in `onRefresh`.

### Current State
- `src/screens/ModelsScreen/ModelsScreen.tsx:185-254` — `handleAddLocalModel` function
  - Line 230: Deletes old file on "Replace" but does NOT remove the old model entry
  - Line 248: `await RNFS.copyFile(file.uri, permanentPath)` — no progress indicator
  - Line 249: `await modelStore.addLocalModel(permanentPath)` — always creates new entry (new UUID)
  - Line 250: `setTrigger(prev => !prev)` — redundant MobX re-render hack
- `src/store/ModelStore.ts:2094-2128` — `addLocalModel` method: always creates a new model with `uuidv4()`
- `src/screens/ModelsScreen/ModelsScreen.tsx:38` — `const [_, setTrigger] = useState<boolean>(false)` declared
- `src/screens/ModelsScreen/ModelsScreen.tsx:109` — `setTrigger` also used in `onRefresh`

### Target State
- **Spinner + status text** shown during file copy (indeterminate since `RNFS.copyFile` has no progress callback)
- **"Replace" removes the old model entry** from the store before adding the new one
- **`setTrigger` hack removed** — MobX reactivity handles list updates
- **FAB disabled during copy** — prevents double-tap launching a second copy
- **Copy errors shown to user** — Alert with error message on `copyFile` failure
- Model list updates immediately after copy completes (already works via MobX, just obscured by missing feedback)

removeModelByFullPath = (fullPath: string) => {

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| `removeModelByFullPath` removes wrong model if two models share a path (edge case after "Keep Both" then rename) | Low | Low | Filter by `isLocal`/`origin === LOCAL` AND `fullPath` match — both must match |

| `RNFS.copyFile` error silently swallowed | Low | Medium | Explicit `catch` block shows `Alert.alert` with error message; `finally` resets `isCopyingModel` so UI never gets stuck |
