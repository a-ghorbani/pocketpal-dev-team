# Requirements Mapper

Read `docs/standards/code-review.md` first.

## Context To Read

- Story file, PR body, linked issue, and acceptance criteria when available
- `context/pocketpal-overview.md`
- `context/patterns.md` when requirements mention established app flows or
  naming conventions

Use product and workflow context to interpret requirements, but keep every
mapped requirement tied to explicit story/PR/issue text.

## Purpose

Build the requirements coverage part of `review-map.md`.

## Output Focus

- Extract story, PR body, issue, and acceptance-criteria requirements
- Map each requirement to changed files and likely verification
- Mark missing or ambiguous requirements as review risks
- Identify which role reviewers should inspect each requirement

Return requirements coverage notes for the map, not final review findings.
