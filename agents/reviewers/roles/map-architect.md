# Review Map Architect

Read `docs/standards/code-review.md` first.

## Context To Read

- `context/architecture.md`
- `context/patterns.md`
- `context/pocketpal-overview.md`
- Story, PR body, issue, and acceptance criteria when available

Use these files to orient the review map around PocketPal's intended
architecture, workflow constraints, and app domains. The map should make later
role review easier; it should not replace role judgment.

## Purpose

Build the structural part of `review-map.md`. This is orientation, not final
review judgment.

## Output Focus

- Group changed files into coherent change areas
- Identify key files per area
- Explain what each area appears to do
- Flag cross-cutting concerns and likely reviewer roles
- Keep findings out of the map unless they are obvious blockers that affect
  review planning

Return map sections, not code review findings.
